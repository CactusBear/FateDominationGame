# FD3.9 全卡面 operation 增补分析

## 阅读结论

**不能按“一个特殊效果新增一个 operation”来做。** 现有原语已经能覆盖大量抽弃牌、移区、资源变化、属性修改、复制建牌、条件判断和延迟执行。真正需要补的是少量访问/执行入口，以及卡牌身份、规则修正、反应结算、秘密信息、地图和战斗流程等底层机制。

本文按所有卡面可辨机制的并集整理，不按版本、DIY、待加入、待更新目录取舍。同名牌不同效果全部保留为需求；同机制只提出一套通用能力。正文中的英文 operation 名均为**建议名，不是已存在接口，也不是要求全部新增**。

### 分析范围与可信边界

- 输入：`FD3.9从者御主卡面数据.md` 全部 4633 个编号。
- 纳入：从者、御主、技能、附带攻击、升华技、附属事件/局势、规则补充和带规则文字的卡背。
- 对照：当前工作树中的 operation 与相关结算代码，包含尚未提交的 `CreateCard`、`BuildCard`。
- 收尾时工作树又出现 `AskPlayerOption.gd` 及配套 EffectManager 暂停/恢复代码。本轮未修改这些源码；已补读新入口，故“效果执行中询问玩家并继续执行”不再列为全缺失。秘密/同时提交、排序及嵌套循环里的暂停边界仍需分别验证。
- 本次是全文 OCR 文档分析与源码静态核对，**不是重新逐图校对，也不是实现/运行验收**。
- 源文有 345 条明确写着“未识别到文字”。另有属性图标丢失、数字混排和半句截断。因此本文能覆盖文档可见的机制，不能保证空白图片没有新增机制。
- 分批初筛为 3632 条 analyzed、798 条 non_rule、203 条 unclear。这些标签仅供追踪，特别是 non_rule 不能作为“原图确定没有规则”的证明；总风险附录会再次收集全部空白和已发现残缺。
- 详细原文、编号、机制记录见 `operation_audit/manifest.json`、`coverage_1.json` 至 `coverage_8.json`、各 `batch_*.md`。分批报告是候选草稿，**去重后的最终取舍以本文为准**。
- [全量逐条索引](operation_audit/全量逐条索引.csv)包含全部 4633 条记录；[OCR风险索引](operation_audit/OCR风险索引.md)列出当前显式发现的 402 条去重风险。已用程序核验编号无缺失、无重复；这是覆盖校验，不等于规则实现测试。

## 一、先剔除这些不必新增的 operation

| 需求 | 优先用现有原语组合 | 不能混淆的边界 |
|---|---|---|
| 牌库顶、底、第 X 张、前 N 张随机插入 | `draw_card_by_card` / `draw_card_by_index` 的 `to_index`，配合 `array_length`、`calculate_number`、`random_int` | 下标移动已存在；缺的可能是全局牌区入口、选择 UI 或区域事件，不是另造“置顶/置底”。 |
| 手牌、弃牌、游戏外互相搬牌 | 区域 getter → `draw_card_by_card` | 物理搬牌不自动等于打出、弃置事件、控制权转移或实体注销。 |
| 新建固定牌、自定义牌、独立复制 | `create_card` / `build_card` / `clone_object` → 现有入区/入场/效果登记 | 创建只创建。已有实体“返回”应搬原实例，不能新建一个冒充；有限游戏外库存也不能无限创建。 |
| 随机、骰子、重复执行 | `random_int`、`for_func`、`foreach_func`、`while_func` | 不加 RollDice、MultiDraw 或角色专用循环。多人猜拳不是随机骰子，必须真实秘密选择。 |
| 数值求和、集合收集、不同种类计数 | 外部累加值或结果数组 + 循环 + `edit_num_and_return` / `add_to_array` / `is_in_array` | 不能仅因循环返回最后结果就判定不能累加。只有实际 DSL 无法传递所需状态时才补最小能力。 |
| 比例与取整 | `calculate_number`，在适用数域内组合余数/整除；`edit_num_and_return` 已有向上取整分支 | 正负数、整数/浮点数与 0 必须专项检查，不能重复提一个数学库，也不能默认为所有现有取整均正确。 |
| 普通玩家标记、层数、用量 | 已有 Buff、BaseNumber、数组及 `used_once_effects` / options / 日志 | 不为每个【浪】【境界】【音量】建原语。牌上附件、秘密标记和有限实体标记另需模型支持。 |
| 普通临时效果 | `schedule_effect_on_time_point` + 条件 + 现有动作 | 到期回滚要只撤本来源。调度器不会自动捕获所有局部变量，也不等于能冻结任意对手效果。 |
| 普通换御主/从者 | 卸旧效果、交接附属状态、换角色引用、登记新效果；必要时 `deal_player_cards` | 普通替换优先整理为宏。双御主、多实体、保留独立牌库另属框架需求。 |
| 常规资源、属性、真名、关闭、败北、移动 | 现有 `edit_*`、`release_true_name`、`hide_true_name`、`close_card`、`defeat`、`move/deploy/set_location` | “败北”不是淘汰，“明暗置”不是切换牌面，“移出版图”不是移除游戏。 |
| 普通多选一、选玩家、选牌、选地点、链中询问 | 已有 effects options、`queue_optional_effect_for_players`，收尾新增的 `ask_player_option` 与暂停恢复流程 | 不再建议重复新增 RequestChoice。关联多选的组合、循环暂停、任意排序、秘密/同时提交分别验收，不笼统宣称都已支持或都缺失。 |
| 最终结算时指定游戏胜者 | `set_player_data("victory_override", true, player_id)`；现有 `VictoryResolver` 会收集全部覆盖胜者 | 已有最终胜者覆盖，不能说完全不存在；缺的是任意时点立即结束、淘汰前替代和完整复活。 |

### 源码核对要点

- `assets/scripts/system/operations/DrawCardByCard.gd:7` 与 `DrawCardByIndex.gd:6` 已支持来源/目标数组及目标下标。
- `operations/ForeachFunc.gd:7` 可执行循环体列表；`ForFunc.gd:8` 支持循环体中的变量引用，`EditNumAndReturn.gd:4` 就地修改 BaseNumber。
- `operations/CreateCard.gd:9`、`BuildCard.gd:11` 已分别实现按库名建牌和按完整数据建牌。
- `operations/SetProperty.gd:6` 只写实际存在的属性。字段能写，并不意味着出牌规则、威力查询、UI、日志和清理已经消费它。
- `global/victory_resolver.gd:14` 已消费 `victory_override`，支持多名覆盖胜者；`global/game_progress.gd:222` 当前在最终回合或存活者不足时调用结局判定。立即获胜应补齐调用时机，不重写现有最终胜者规则。

## 二、真正值得考虑新增的基础入口

以下每项先验证现有组合，保留的是**组合缺乏入口或无法维护一致性**的部分。

### A. 全局牌区访问与对象位置查询

**候选**：`get_board_zone(zone_id)`；统一容器模型建立后再考虑 `find_object_zone(object)`。

- 只查询，不抽牌、不洗牌、不入场。
- 取得数组后，顶底插入、随机插入、洗牌继续用已有原语。
- 覆盖事件/局势牌库与弃牌堆、专属牌堆、牌上附件、地图放置区、原始来源位置。
- 证据：伊阿宋派遣 #1—10、白蔷薇的誓言 #131、梦游仙境 #4411、迦勒底亚斯 #4584、密室难题 #4617。
- 缺口：`GetGameDataValue` 访问 GameData，而事件/局势牌堆在 MapData；`FindPlayerArrayContaining` 并非所有容器的地址查询。
- **不要额外新增 `move_board_card` 只为了搬数组**。区域进出事件与效果登记应由容器生命周期统一处理，再复用原有搬运能力。

### B. 同一张牌切换正反面/多形态

**候选**：`switch_card_face(card, face_id, state_policy)`。

- 只切换同一实体的定义，不顺手打出、支付、移区或判胜。
- 数据声明面之间的关系、哪些状态保留、哪些印刷字段变化；不由文件名或卡名猜。
- 保留对象身份、附件、永久修正及卡面要求保留的状态；注销失效效果并正确绑定新效果。
- 明暗置仍使用 `set_card_concealed`，与换面互不替代。
- 证据：机械弓术 #747—755、魔术礼装·亚德 #1615、彼界之门 #4387—4388、咒缚 #4452—4496、菲奥蕾超越 #4537。

### C. 安全附加/摘除结构化效果

**候选**：`attach_effect(target, effect_definition)`、`detach_effect(target, effect_handle)`，两个动作分开。

- 只维护效果与宿主关系及其必要登记不变量，不附带费用/数值/入区行为。
- 复制选择的行动阶段能力、失去某项能力、追加某项能力、替换时点、卡牌名称自指重绑定，都在结构化效果层处理。
- 替换 = 摘除旧项 + 附加新项；不要新增 `copy_or_replace_everything` 万能入口。
- 普通名称、费用、威力、属性复制，继续由 getter、clone 值和 edit 原语组合。
- “失去所有卡牌文字”还涉及词条、条件和被动规则，不能仅删除当前已登记的主动 funcs。
- 证据：龙种改造 #31、刀剑审美 #99、卢恩魔术 #455、颉颃胜负 #488、游身步 #4083、魅力展现 #4440、直至顶端 #4624。

### D. 指定效果的再次发动

**候选**：`invoke_effect(effect_handle, execution_context)`。

- 只请求发动指定效果，仍走原来的费用、选择、次数、反制和日志流程。
- 是否免费用、无视阶段、无视前提、再次使用，由调用方显式给定有限例外，不默认绕过所有限制。
- 不用广播时点模拟一张指定牌的行动能力，避免把其他牌一起触发。
- 证据：阴阳螺旋 #34、隐藏不贞的头盔 #214、尼莫护士 #998、女武神的叙语 #1670、无极 #4301、弃牌堆发动鸦群 #4442。

### E. 控制权交接

**条件候选**：`set_card_controller(card, player_id)`。

- 只有建立 owner/controller 分离后才有明确语义；若已有原语加宏能完整、安全完成交接，则不新增。
- 原拥有者、当前控制者、效果归属、关闭后的归还区域是不同概念。
- 不随便改写 `from` 来抹掉来源；借用期限和归还仍由调用方调度。
- 证据：侥幸的拘捕网 #264、贯穿之朱枪 #461、终焉的大木马 #961、侵蚀 #4166、天之锁 #4319。

### F. 真正同时发生的交换

**条件候选**：`swap_player_locations(a, b, movement_policy)`。

- 仅为规则要求同时交换、不能被席位上限或中间态反应破坏的情形保留。
- 普通依次移动继续 `foreach_func` + `set_location`；交换两张普通数组里的牌先用保留引用/下标的组合，不因链长就加原语。
- 必须声明是否视为移动、是否保留地利、是否受阻，不自动给交换附加规则。
- 证据：海神，凶猛狂暴大海啸 #316，以及位置交换类效果。牌库同位置交换 #141 属牌区操作，不与棋子交换混为一个函数。

### 不应打包成万能 operation

- 不做 `manage_card` 一次完成创建、翻面、移区、打出与归还。
- 不做 `edit_map_topology(change)` 接受任意杂项命令；拆到单个拓扑动作。
- 不做 `resolve_alternate_victory` 同时处理战场胜者、游戏胜利、复活和追加回合。
- 不做 `manage_marker` 同时创建实体、改变数值、公开信息和到期移除。普通数值复用现有操作，宿主与可见性分层。
- 不做 `copy_skill_with_overrides` 仅仅包装已有 clone、edit、入区序列。只有无法维护效果绑定的那部分才补入口。

## 四、典型复杂卡如何拆，不写角色专用 operation

### 伊阿宋派遣

1. 找到原牌实例，切换其派遣面。
2. 取得事件牌堆，在数据指定的前 N 张范围内随机插入原实例。
3. 事件抽取管线识别“这不是事件牌”，按卡数据替换本次抽取。
4. 到场后切回，将其加入攻击；原地点补事件。

新缺口是实体牌堆生命周期、全局区访问、切面、抽取替代；不是“派遣”“召回阿耳戈”两个专用函数。

### 恩奇都变容

1. 玩家选择基础牌，移入变容的附属区。
2. 按附属区顶牌提供费用、威力、属性和效果的动态投影。
3. 弃置附件后重算投影，把弃置牌的属性按数据规则赋予攻击。

新缺口是附件区与动态定义/效果投影；抽牌、弃牌、属性增加仍用已有原语。

### 爱丽丝双棋子

1. 创建归同一玩家所有的第二棋子。
2. 出牌只发生一次，共享卡；两个战场各自计算局部威力。
3. 地点相关效果由玩家选择一个来源地点。
4. 同处一地时按一名玩家参与战斗；跟随移动按路径和可移动性结算。

不能复制整个 player_data，也不能把两个棋子数成两名交战对手。

### 芙兰切斯卡幻术

1. 效果开始判定幻术是否为合法目标。
2. 玩家对本次判定选择哪些特征视为符合。
3. 在当前查询上下文应用局部覆盖；效果结束后丢弃上下文。

不能永久改牌名/印刷值，也不能通过“先改后恢复”污染同期其他效果。

### 蓄势

1. 读取实际费用，算出卡面位置并检查牌库长度。
2. 用已有数组转移插入第 X 张。
3. 记录这张实体的蓄势状态。
4. 无论因抽取、弃置还是其他原因离开牌库，统一离库事件将其免费加入攻击。

位置操作无需新增；真正要补的是离区事件完整性和替代结算。

## 五、建议实现顺序与验收

### 第一层：不改规则模型也能先验证的复用

- 为顶底/任意插入、累计数值、去重、范围收集、普通标记、骰子、普通角色替换编写真实 JSON 组合测试。
- 只有组合实际无法表达时，才提出新的最小原语。
- 验收必须覆盖空数组、单元素、同源同目标、卡不存在、容量不足、同一对象多次引用、负数/0与取整边界。

### 第二层：卡、效果和事件基础

- 明确牌实例身份、owner/controller、容器、附件、效果来源与修正层。
- 实现必要的查询、切面、效果挂卸、指定能力调用入口。
- 验收：同一实体不能同时留在两个互斥牌区；重绑不重复触发；永久影响不因切面被抹掉；临时影响到期只撤自己；有限游戏外牌不会凭空复制。

### 第三层：反应、支付与交互

- 建立即将发生/已完成事件、支付事务、目标替换、有限例外、可见性与关联选择。
- 验收：被阻止不先扣费；对手代付被正确记账；被阻止尝试仍可供卡面引用；秘密选择不提前泄露；等待选择时其他效果不能越过结算点。

### 第四层：战斗、阶段和地图扩展

- 增加目标战场结算、游戏胜负/淘汰替代、额外流程、地图编辑、多实体与NPC。
- 验收：提前结算不重复发奖；改判在发奖前；两个爱丽丝算一个对手；动态地图的UI、可达性和部署检查一致；回合重跑遵守已确认的保留策略。

### 第五层：数据接线与真实运行

- 将各卡面差异表达为参数和声明，不写死角色名、数字、阵营、时点或地图名。
- 新增接口须接 `all_operations.gd`、加载器/编辑器参数、克隆语义、日志、AI与UI。
- 至少按上述典型机制编写 Godot 专项测试，并实际非 headless 跑局验证影响规则和UI的改动。
- 本次不实施代码，不把上述验收事项标成已通过。
