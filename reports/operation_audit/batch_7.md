# source_7 卡面 operation 审计（3481—4060）

## 范围与口径

- 已依编号逐条审阅 `source_7.md` 的 580 条 OCR/转录文本，未按“旧版、更新版、衍生卡、待加入”等目录排除；重复卡面也分别记入 `coverage_7.json`。
- 本批只审计文本与源码，没有查看原图，不能把 OCR 文本当作原图复核结论。
- 对照了 `assets/scripts/system/global/all_operations.gd` 当前 195 个登记项及相关 `operations/*.gd` 源码；未提交的 `CreateCard.gd`、`BuildCard.gd` 也按现有能力计算。
- 判定顺序是“现有 operation 组合 → 单一职责新增候选 → 需要底层/交互框架支持”。`SetProperty` 只能写已经存在的字段，不代表支付替代、可见性、双棋子、事件槽、阶段替换等规则已经实现。

## 已有原语与可复用组合

1. **数值与条件**：`get_data_number/get_player_data_value/get_current_round/query_log/sum_log_data/log_exists` + `calculate_number/compare_number/if_func` + `edit_magic/edit_score/edit_power/edit_data_number`，可表达大部分按回合、资源、胜负历史计算的增减。
2. **卡牌筛选与区域搬运**：`get_player_*`、`merge_arrays`、`get_cards_by_name_fr_arr/get_cards_by_attributes_fr_arr/filter_by_property`、`draw_card_by_card/draw_card_by_index`、`shuffle_array`，可完成已知数组间搬牌、洗牌、移出游戏、置顶/置底。
3. **构造**：`create_card` 能从已加载的攻击/事件/局势/令咒模板创建独立实例；`build_card` 能按完整 JSON 数据创建 attack/skill/upgrade_skill/buff/thing/event/situation/command_spell；二者都只负责构造，放区与登记仍组合 `add_to_array/register_object_effects`。
4. **卡牌编辑**：`edit_card_power/edit_card_cost/edit_card_attributes/set_card_concealed/close_card` 已覆盖威力、费用、属性、明暗置和关闭；`clone_object` 可复制对象。但没有“替换/附加卡牌效果文本”的受控原语。
5. **地图与行动**：`deploy/set_location/move/move_location/get_move_target_location` 可部署、效果搬运、正逆向常规移动；`SetLocation` 能选择是否按常规移动检查进入限制及是否忽略人数上限。`set_map_area_can_move_to`、`set_location_pl_num_limit` 及 restore 配对可改进入/席位规则。
6. **事件与延迟**：`add_event_from_deck/add_map_area_events/get_events` 可从循环事件牌堆取克隆体并入场；`schedule_effect_on_time_point` 能登记一次性后续效果；`emit_time_point` 能派发时点。
7. **胜负、真名与效果登记**：`defeat/remove_defeat`、`release_true_name/hide_true_name`、`register_object_effects/unregister_object_effects/counter` 已可组合常规败北、真名切换与能力挂卸。
8. **现成可组合例**：3486“唯一末位”可用 `get_rank_by_data_number + array_length + compare_number`；3503/3926 临时加入【幻想大剑】可用 `create_card + add_skill_to_skill_zone + schedule_effect_on_time_point`；3595 事件战果可用 `get_events + get_event_printed_score + edit_score + draw_card_by_card`；3934 临时技能区组合亦不需要角色专用 operation。

## 单一职责新增候选

以下候选按能力去重；同一候选下列出精确卡面编号和卡名。

### 1. 查询并重排牌库区段（`peek_cards` / `reorder_cards`）

- **卡面**：3507【王之遗物】、3559【神秘代码：CCC】、3789【小小希望】、3815【遗留给未来的遥远赠礼】、3825【纪行】、3964【红玉之书】、4010/4013【生·切断】、4012【死·紧握】、4014【两仪式】。
- **不足**：`get_card_by_index_fr_arr` 只能逐下标取对象，`draw_card_by_*` 只能已知对象搬运；没有返回“顶/底 N 张”的稳定快照，也没有按玩家选择结果一次性重排剩余牌的原语。
- **复用**：查询结果继续交给 `draw_card_by_card`、`shuffle_array`、`add_to_array`；新原语不负责弃置、抽牌或 UI 选择。

### 2. 交换两张卡在各自容器中的位置（`swap_cards_between_arrays`）

- **卡面**：3513【月灵晶体】、3671【皮斯曼】、3694【规则操作】、3753/3754【月之癌】、4010/4013【生·切断】。
- **不足**：可以手工两次 remove/add，但跨两个数组、同数组交换时中途下标变化，JSON 链很难保证原子性。
- **复用**：容器仍由 `get_events/get_player_* / find_player_array_containing` 获取；候选只交换，不负责翻面或触发入场。

### 3. 取得对象当前所在容器及下标（`find_object_container_index`）

- **卡面**：3513【月灵晶体】、3694【规则操作】、3972【秘剑·比翼闪耀】、4010/4013【生·切断】以及所有“返回原本所在位置”的卡。
- **不足**：`find_player_array_containing` 仅覆盖玩家区域且只返回数组，不返回下标；事件槽、御主牌上附牌、地点附着物不在其范围。
- **复用**：与 `draw_card_by_card/draw_card_by_index`、上项交换原语组合。

### 4. 为卡牌附加/移除结构化效果（`add_card_effect` / `remove_card_effect`）

- **卡面**：3501【另一个结局】、3516【投影魔术】、3521【对魔力】、3532/3534【黑羽】、3564【投影魔术】、3635【人理保障天球】、3708【紫苑】、3724/3750【狂战士EX】、3768【他人格】、3837【芙芙】、3966—3970【五型】、4015【空之境界】。
- **不足**：`set_property` 写 `_effects` 不会自动处理 `from`、触发玩家、登记/注销与克隆语义；`register_object_effects` 只登记已经存在的效果。
- **复用**：效果对象可由 `create_func/create_base_number` 和现有加载器构造；新增项只维护“卡—效果”关系，登记仍显式组合。

### 5. 通用计数/标记容器操作（`get_counter` / `edit_counter`）

- **卡面**：3643【冠位指定】、3709/3730/3733【迦勒底·图书馆】、3720/3744【阵地作成EX】、3798/3800/3826【记忆】、3962【宫本伊织】。
- **不足**：`edit_data_number` 只面向 player_data；卡牌、地点、事件上的计数没有统一模型。把任意 `_numbers` 当标记会混淆印刷数值与运行态计数。
- **复用**：比较和公式继续用 `calculate_number/compare_number`；候选只读写指定对象的具名运行态计数。

### 6. 翻转/切换双面对象（`flip_card_side`）

- **卡面**：3674—3694【原罪/美德】组、3891/3892【敏锐嗅觉/自我欺骗】、4017—4031【两仪式/阴阳鱼】。
- **不足**：`set_card_concealed` 是明暗置，不是正反面数据切换；`set_property` 不能同步名称、图像、效果注销/重登记和运行状态。
- **复用**：切换后使用 `unregister_object_effects/register_object_effects`，区域不变。

### 7. 取得牌的当前印刷/运行态规则特征（`card_matches_rule_traits`）

- **卡面**：3517【无限剑制】、3578【干将·莫邪】、3584【骑乘】、3585【气息遮断】、3714【守护EX】、3767【裁决者】、3964【红玉之书】、3971【五轮之刃】、4010/4013【生·切断】。
- **不足**：现有查询分散为属性、印刷费用、印刷威力、tag、效果名，无法统一区分“印刷属性/当前属性、基础/技能/残留/临时、正面/暗置”。复杂筛选会重复写长链且容易把运行态当印刷态。
- **复用**：候选只返回布尔值；筛选循环仍用 `foreach_func/if_func`。

### 8. 将卡送回拥有者的规则区域（`return_card_to_owner_zone`）

- **卡面**：3484【芙芙（玩偶服）】、3528【特里姆玛乌】、3578【干将·莫邪】、3703—3705【魔神柱】、3778【天赋的睿智】、3837【芙芙】。
- **不足**：当前只能由调用方知道类型并选数组；技能返回技能区还必须登记效果，攻击牌返回手牌/牌库/弃牌的语义各异。
- **复用**：底层搬运继续用 `draw_card_by_card`，技能区接线复用 `add_skill_to_skill_zone`；原语只负责按显式目标枚举路由，不掺关闭或费用结算。

### 9. 操作玩家的令咒实例（`gain_command_spell` / `spend_command_spell` / `restore_command_spells`）

- **卡面**：3503【邪龙传说】、3601【爆了】、3611/3618【生命之海/提亚马特】、3674【炽天之槛】、3705【魔神柱巴巴妥司】、3715/3740/3767【裁决者令咒】、3783/3784【拟似令咒】、3794/3796/3803/3804【记忆】、3928【第二类永动机碎片】。
- **不足**：把 `command_spell_count` 当数字可做比较，却不能保留令咒对象类型、来源、上限例外、移出游戏和“印戒/拟似令咒/裁决者令咒”的实体语义。
- **复用**：实例构造用 `create_card(card_type="command_spell")`，区域用 `get_pl_command_spell_side/out_game + draw_card_by_card`；候选只统一支付/恢复与日志时点。

### 10. 查询/设置玩家规则身份或职阶集合（`get_player_classes` / `edit_player_classes`）

- **卡面**：3488【黑键】、3718/3719/3743/3746/3749【月之癌EX】、3799/3824【月之可能性】、3938【盈月之主】。
- **不足**：`set_property("_servant_class", …)` 只能覆盖单值，不能表达“同时视为”“临时视为”和来源撤销。
- **复用**：候选维护带来源的集合；卡牌属性查询仍用现有 `has_attribute`。

### 11. 将现有卡替换成另一模板并保持区域（`replace_card_instance`）

- **卡面**：3601【爆了】、3708【紫苑】、3729—3734【迦勒底设施】、3735/3736【旧版紫苑】、3831【胖所长】、3851【真祖】、3946【盈月的怪物】、3947【地右卫门】、3962/3964【宫本伊织/红玉之书】。
- **不足**：`create_card/build_card + draw_card_by_card` 能造与搬，但没有原子替换、保持原区域下标、注销旧效果并登记新效果的单一入口。
- **复用**：构造必须复用 `create_card/build_card`；不把“替换哪些卡”写死在原语里。

### 12. 选择并执行卡上指定阶段能力（`invoke_card_effect_by_timing`）

- **卡面**：3890/3916/3920【贝利尔·伽特】、3957/3958【家族秘术/科耶特繁荣永存】。
- **不足**：现有 operation 能登记/注销/反制效果，但不能安全枚举某卡“行动阶段能力”并按原效果上下文执行；直接调用 funcs 会绕过每回合限次、来源与支付。
- **复用**：选择留在场景层；候选只解析并提交指定效果，仍走 EffectManager 正常结算。

### 13. 按规则复制技能并写入来源/限次（`copy_skill_with_overrides`）

- **卡面**：3564【投影魔术】、3890/3917【直到地狱尽头】、4000【太平之愿】。
- **不足**：`clone_object` 可复制对象，但“属于谁、是否每局限一次、放回哪个独立技能区、原对象效果是否登记”需要一致处理；`set_property` 拼接容易漏效果上下文。
- **复用**：底层复用 `clone_object + add_skill_to_skill_zone + register_object_effects`；覆盖项由调用方显式给出。

## 框架层缺口（不能靠新增一个 operation 假装完成）

1. **玩家选择/秘密选择/猜拳与宣言 UI**：3500【月之胜利者】、3512/3514【叛逆之刃】、3513【月灵晶体】、3580【挑战结果】、3643/3664【沃戴姆】、3694【规则操作】。operation 可提供候选数据，但必须有可暂停效果链、按玩家可见性提交结果的交互框架。
2. **席位占领与部署预约**：3482【第二魔法式宝石制精练成阵】要求多个位置“占据”、禁止他人部署、到行动阶段再部署；当前 `BaseLocation._players/_pl_num_limit` 只表示实际落位，不表示带所有者和期限的预约。
3. **多棋子/同一玩家多位置**：3579/3597/3598【幻影爱丽丝】要求同一玩家两个棋子、共享牌但分地点战力；当前权威位置仍是单个 `location`。`temp_locations` 虽已声明并在回合开始清空，但没有其他规则/UI 消费者；`SetLocation` 仍会从旧位置摘除，必须先扩展战斗参与者、战力归属与 UI，不能把写入 `temp_locations` 当作完成。
4. **NPC 与独立战力实体**：3853/3884【始皇帝】、3894—3913【妖精骑士/摩根】需要非玩家参与者、独立位置/战力/胜负归属；不是 `set_player_data` 能补出的字段。
5. **自定义独立牌区/牌堆**：3611—3615【魔兽】、3675—3694【原罪/美德】、3784—3827【记忆】、3993—4003【无主从者】、4032—4053【兽】。现有 player_data 固定区与通用数组搬运不足以提供抽取规则、可见性、弃牌堆、UI 和生命周期。
6. **胜负/淘汰替代与共同胜利**：3556【阿瓦隆】、3599【被污染的圣杯】、3669【救世主】、3780/3782【诀别之时】、3834【苍天之力】要求可拦截淘汰、替换御主、共同胜利或强制胜者；应由胜负结算管线提供可替代事件，而不是效果直接写 `is_out`。
7. **来源过滤的免疫/规则覆盖**：3498【求道者的愿景】、3521【对魔力】、3592【绞首刑之雷：特殊】、3711【他人格EX】、3718【月之癌EX】、3970【地之型】需要知道修改来源并阻止/反转特定类别；当前普通数值写入后来源信息不足。
8. **临时重建手牌与改写常规出牌规则**：3517/3581【无限剑制】涉及从多个区域选牌形成临时手牌、0—4 张常规出牌、禁止抽牌和结束条件，需出牌批次/临时区框架。
9. **动态事件牌堆、事件槽与异闻带扩张**：3642/3657—3664、3841—3853、3893—3913 需要游戏外事件池、事件槽替换、同步扩张和 NPC 归属；`add_event_from_deck` 只轮转现有 `MapData.event_deck` 的顶部模板。
10. **牌面永久变更与回滚来源**：3484/3837、3791/3805、3709/3729—3734 等要求费用下限、永久修改、覆盖/恢复原技能。若只 `edit_card_cost/set_property`，无法按来源撤销、显示修正历史或保证印刷值下限。
11. **阶段替换与额外阶段**：3498、3619—3626、3784、3940 等有“不在准备阶段抽牌”“准备阶段进行前哨及行动阶段”等规则，需要阶段调度器支持，不能只发一个时点。

## 本批结论

大多数数值增减、筛卡、搬区、创建已知卡、真名切换、败北、普通移动和一次性延迟效果可以由现有原语组合。主要 operation 缺口集中在“容器位置/交换、具名计数、双面切换、受控追加效果、令咒实例、卡替换与指定能力调用”；多棋子、NPC、独立牌区、胜负替代、来源免疫、阶段替换和动态事件槽属于框架层，不能用角色专用 operation 或裸 `SetProperty` 掩盖。
