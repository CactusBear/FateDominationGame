# 身份继承正式大厅接线说明（实施前）

本批只修改正式大厅场景、大厅控制器，并新增身份继承子窗口场景和控制器；身份认证、候选生成、请求序号、恢复票据、事务落盘完全复用既有 lobby_session、identity_inheritance_input 和 member_identity_bindings。禁止启动 Godot、访问凭证、提交代码，不修改 v2、网关、工作进程、效果引擎。

## 界面与代码职责
1. 大厅 Actions 增加“指定身份继承”按钮。仅独立服务端、已认证、当前在线房主且所选原成员掉线时允许打开。目标使用现有成员列表 metadata 内稳定 member_id，不根据昵称找成员。
2. 独立 identity_inheritance_panel.tscn 使用原生 Window，固定说明、原身份名称、候选 ItemList、刷新/确认/关闭按钮和状态区均写入场景。明确先拒绝身份不符，再由房主指定；候选须以新用户身份观战加入，继承后由会话私有交付凭据。窗口不读取/显示任何密钥、指纹或票据。
3. 子窗口控制器复用 identity_inheritance_input.accept/select_member/request_args。候选只取服务端 label 和 member_id，服务端负责昵称及重名附用户名；客户端不拆分 label、不自行合并昵称、不给 member_id 配可见文本。ItemList metadata 仅保存 member_id，确认按 metadata 取得稳定身份。
4. 打开/刷新发送 identity_candidates 空参数，收到合法且与当前房间 revision 一致的模型后填充列表；未查询、已关闭、权限已丢失和修订不一致的迟到回复不显示。确认通过 request_args 绑定 target_member、successor_member、revision，再调用 session.request("identity_inherit", args)；序号下限由既有会话消费 request_floor，不在 UI 重造计数器。提交后清选择且禁用重复提交，等待权威房间更新，不把发送成功当继承成功。
5. 权限变化、房间 revision 变化、目标恢复在线/消失、断线、请求失败、刷新和关闭都清除输入模型和列表选择。大厅每帧检查窗口上下文，覆盖没有 changed 信号的传输断线。窗口只显示自己的固定中文失败提示，不将网络错误字典、密钥或票据内容拼进可见文本。
6. 大厅拒绝回调同步清除身份窗口选择；离开、重新建房/加入的清理路径关闭窗口；切入对局时窗口随大厅销毁。窗口信号只在 ready 接一次，专门解除会话候选信号避免失效回调。
7. 新增 scratch 专项窗口测试源码，供主代理后续复制/执行：真实鼠标选择重复昵称标签，按稳定 metadata 请求，断言版本、权限、失败、断线清理及不自动选择。静态检查仅验证 GDScript 文法、场景引用/节点路径、diff 空白和源码契约；不以静态结果代替 Godot 加载、网络权限、继承落盘、窗口布局或真实点击运行验收。

## 已查明的真实协议
- 查询 identity_candidates；提交 identity_inherit。
- inheritance_candidates_received(model) 携 revision、request_floor、candidates；每个候选严格为 member_id 与 label。
- 既有候选只包含在线未绑定席位的观战成员，权威端验证已认证房主。
- inheritance_ticket_received 只报告成员 ID，票据原文由 session 私有保存，原观战连接断开前不能启用。本批不自动断线、不自动激活票据，不冒充旧席位已恢复。

## 不采用的方案
不修改业务模型，不以列表下标/昵称/指纹提交，不自动选择第一项，不让首个持票者认领，不新增用户名猜测规则，不直接切换观战连接授权身份，也不在大厅展示私有票据。成功发送仅显示“已提交，等待房间更新”。
