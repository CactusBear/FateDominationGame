## 管理员用法
`room <id> legacy-approve <pid> <instance_id> legacy_approved '{"2":7,"3":8}'`

JSON 键是旧稳定成员编号，值是管理员明确选择的当前已认证网关连接编号，不是 fingerprint 或 token。必须覆盖全部成员，不能将同一连接/认证密钥重复分给两个成员。PID 与 instance_id 来自当前登记；休眠登记允许其实际 PID=-1，但实例仍必须准确匹配。

`room <id> legacy-reject <pid> <instance_id>`

拒绝只记录固定操作人标签和成员编号，不改旧档、不启动恢复。普通公网管理员即使有 admin 权限也不能执行这两条命令。

## 尚未运行验收与整合边界
- Windows 原生 File.Replace、POSIX rename、磁盘故障、真实认证连接单播与旧席位恢复没有运行验收，不能宣称实机迁移成功。
- 目标必须已在 manager.rooms 中登记，且工作进程已退出。当前旧档发现流程如会因为缺少身份绑定拒绝建休眠登记，需要主代理在其所有权范围审查接入；本批没有修改 manager 或 worker。
- 票据只在落盘成功后私有单播。回执 delivery_confirmed=false 表示没有客户端接收确认；失败时 persisted=true 与 delivery_failed 明确区分。当前没有新增私有票据重投/确认机制，发送失败不能当恢复成功；新票据不会写盘或进入控制台回执。
- Windows 不走会先删目标的 DirAccess.rename；使用受信登记路径构造转义后的 PowerShell File.Replace，失败关闭并保留备份。前提是管理存储由可信本机用户独占；字节比较不能代替跨进程目录锁，已经拒绝存活 worker。
- 本批为批准写入 legacy_identity_audit（成员编号、固定操作人标签、批准动作）；既有 inheritance_audit 仍遵循原验证器的五个整数字段，没有混入指纹或 token。后续会话再导出时是否保留新增审计字段属于主流程整合范围，本批没有改身份核心。
