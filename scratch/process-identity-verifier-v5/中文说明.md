# Worker OS 进程所有权验证：明确失败关闭

## 查证与范围
实际生产路径已迁移为 `scripts/net/server/server_room_manager.gd` 和 `scripts/net/session/authority_host_client.gd`。本批只修改这两份独占文件，禁止 Godot、凭证与 commit。

已有 FateServerSignals GDExtension 仅绑定 enable/protect_worker/disable/take_request；protect_worker 处理控制台信号，不取得或保留子进程 OS 句柄。其他登记扩展是 WebRTC 和 Git 插件。manager 使用 OS.create_process 返回 PID，ready 与 supervisor 是本机 JSON 的实例关联，既没有由 spawn 原子取得的进程句柄，也没有可信创建时间/进程实例凭证。Callable 默认无效使 is_ready 永久 false，poll 却可将 room.ready 置 true，房主端没有错误便永久等待。因此不能接一个 PID 存活检查或 ready 自报字符串来伪造安全实现。

## 修改前逐项代码说明
1. manager 保留现有 verifier Callable 的兼容接口，但新增 `process_ownership_available()` 能力接口。本版本固定返回 false，并给出统一中文不可用原因；Callable 不能自行解除原生能力阻断。将来必须在原生生命周期完整接线后替换该能力接口。
2. create_room 和 recover_room 在任何路径创建、配置发布、端口探测和进程启动前拒绝。这样 LAN/P2P 与 dedicated 共享同一失败关闭边界，不遗留注定无法通过所有权验证的新 worker。
3. process_identity_verified 在检查绑定和回调前检查原生能力，拒绝 ready 自报、裸 PID 和任意布尔回调绕过；保留严格 bool 结果约束。
4. poll 在读 ready 或写 supervisor 前清除登记 ready 并写明确 room.error，保留目录和进程，不将未验证 PID 当成可安全终止的所有进程。stop_room 和析构也在正 PID 的 OS 操作之前拒绝，避免误杀 PID 重用目标。
5. authority_host_client.start 在开启监听/接管 P2P peer 前读取同一能力接口，返回 ERR_UNAVAILABLE 与明确错误，不把房主挂在永久等待状态；只改接线区块，不改其它代理负责的关闭流程。
6. scratch 静态 source 契约检查覆盖 bool 恒真回调、PID 存活、ready 自报、恢复副作用、poll 假绿、停止与析构操作；在内存对源码做反例变异，要求检测器报红，不实现 Python 游戏规则替身。

## 真正实现计划（未实施，当前不可用）
- 扩展原生模块或独立原生生命周期类统一负责 spawn/verify/is_exited/terminate/release，禁止先 OS.create_process 再凭裸 PID OpenProcess 认领。Windows 从 CreateProcessW 返回时保留 HANDLE 并取得创建时间，Linux 在受控 spawn/reap 生命周期里保留 pidfd 或等价不重用身份，其他平台必须提供等价原语，否则继续失败关闭。
- 原生所有者在创建时绑定 room、authority_host_mode、instance_id、返回 PID 和私有不透明句柄 token；token 不从 ready/config/recovery 自报恢复。管理器及 LAN/P2P 房主只使用生命周期所有者；dedicated 使用同一原语。
- ready/supervisor 继续作为应用层握手，但不能自证 OS 所有权；每次 ready、路由、控制、kill 和真实退出确认均用原生句柄。安全关闭回执与真实退出分开判断；进程退出、重启、owner 析构释放句柄且旧实例不能命中新实例。
- 主管重启发现旧房间只登记离线恢复目标，不依据 PID 自动认领；必要管理迁移必须显式授权。
- 验收覆盖 PID 重用、旧 ready 重放、假 bool 回调、跨 host mode、句柄关闭/失效、spawn/退出竞态、保存失败保留原进程，以及真实安全关闭。须原生构建与 Godot 串行运行验收后才可将能力接口开放。
