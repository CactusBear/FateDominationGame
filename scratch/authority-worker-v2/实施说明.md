# 权威工作进程位置与生命周期补齐

本批只修改 server_room_manager.gd、server_room_worker.gd、server_bootstrap.gd，保留 worker 已有 protect_worker 原生信号保护与 _gateway_identity_required 身份接线；server_process_signals.gd 无需改动。网关和本机 UI/传输入口不属本代理所有，只交付待合并补丁及明确接入说明。

1. 管理器增加显式 authority_host_mode：dedicated 表示独立服务端本机启动，lan/p2p 表示房主本机启动。所有模式都只使用 OS.create_process 启动当前机器上的规则子进程，内部端口仍是回环；不能把 P2P 信令机当权威。模式在本机启动配置写明，不进入公开规则 settings，不从远程客户任意选择。
2. 每次启动及恢复生成随机 instance_id，与 pid、room_id 一起验证 ready、主管心跳及管理实例。实例值复用 control.instance_id 接线，兼容既有管理通道的 instance 字段；ready 增加规范 instance_id、room_id、authority_host_mode 和能力对象。能力区分真实引擎接口可用、当前检查点可回滚、审计/录制状态，绝不把杀进程描述成根事务回滚。
3. 恢复启动前更新本机配置实例、清除过期 ready；每个实例单独 engine 日志，避免旧错误污染。恢复不删除目录、恢复文件或存档。调用方可提供预期旧 pid+instance_id 进行 compare-and-swap 恢复/停止；网关补丁提供此绑定。停止仅是生命周期操作，非规则回滚。
4. 主管心跳与 worker 当前实例绑定，避免旧主管文件或 PID 复用误认。ready 不再通过同步读完整引擎日志决定能否传输，启动错误以 worker 的 ready/退出状态为准。
5. bootstrap 声明 signaling-only 入口，仅进入现有信令场景，不装载房间 worker/规则；不更改公共启动默认值。导出版全局 autoload 是否仍加载规则属项目导出配置边界，交接如实说明。
6. 事务代理已新增 MatchJournal.audit_event/begin_audit/end_audit：复用该持久审计接口，录制开启时由现有 MatchReplay 负责事务审计文件；录制关闭时 worker 创建独立的 transactions.<instance_id>.log，关闭时只释放自己持有的审计写入器。审计文件失败会明确报告，不能把内存审计冒充持久化成功；不把完整日志扫描塞入网关 poll。
7. 新增独立 GDScript 专项及 Python 静态契约检查；不启动 Godot、不用凭证、不提交 commit。用可用 GDScript 解析器做静态语法验证；运行静态专项并导出本批生产 diff。运行时专项交主代理串行验收。
