# 恢复路径安全实施说明

本代理独占 server_room_manager.gd 的发现/恢复入口和 server_room_worker.gd。保持已存在的策略、实例标识、密钥绑定和身份接线，不修改 gateway/lobby/effect/journal，不启动 Godot、不读取凭证、不提交。

实现前说明：新增 RecoveryPathSafety 只负责本机路径授权检查。先逐段拒绝空段、点段、保留设备名、ADS、尾点尾空格，再按完整路径段比较授权根；大小写仅在 Windows 比较，不用 simplify_path 把恶意输入洗白。逐层检查根祖先及子路径的链接，缺少必要目录时拒绝。发现和恢复都重新验证配置 directory、批准 data 根及配置/恢复文件。工作进程从独立启动参数取得批准数据根与房间根，不能让可修改配置自证授权。

工作进程在读 data、已有固定副本、恢复日志之前重复做边界检查；缓存内容在首次 store 前 pin，保持到组装、加载、发布结束，失败/退出释放。恢复原档只读：恢复前复制经过逐层非链接检查的存档到本实例专属目录，在副本执行恢复和后续录制；失败保留原档。

边界：Godot 的 DirAccess/FileAccess 没有 openat/O_NOFOLLOW 或 Windows reparse-safe 原生句柄接口，重复路径检查不能消除同权限恶意本机进程在检查和 open 之间替换目录的最后竞争窗口。此实现需要房间目录对不可信系统账户不可写；静态交付不能声称操作系统级 TOCTOU 已完全消除。缓存通用损坏 blob/.part 清理预算由缓存所有者处理，不跨写其生产文件。

交付包含 GDScript 路径专项及静态 parser/diff 检查，Godot 运行专项留给主代理串行执行。
