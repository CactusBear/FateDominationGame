## 主代理必须对账的边界
1. 同权限恶意本机进程可以在 DirAccess 检查与 FileAccess.open 之间交换目录；纯 GDScript 未提供原生句柄级 no-follow/reparse-safe 锁定。已加读写前后复查、内容哈希以及原档私有副本，**不可宣称系统级 TOCTOU 完全关闭**。批准根/房间根需不可信系统账户不可写；若验收要求防同权限替换，需要原生安全句柄桥。
2. 非默认 data_root 的主管进程重启发现恢复：网关在调用 discover_rooms 前应从受信任本机 `listen(root)` 设置 `rooms.approved_data_root = root`（按实际属性名接线）。我无 gateway 所有权，未跨写；默认值是 LoadHelper 的正常 data 根，不能从旧房间 config 反向提升批准范围。
3. 损坏 blob/.part 清理预算属于缓存代理，未跨写 content_cache/assembler/validator；本代理补工作进程从 store 到固定副本发布的额外 pin。
4. 工具两次提示 `server_room_manager.gd` 被兄弟 sa-1-6a2e40da 修改。我的操作均为独立函数/唯一锚点 patch，已见其 process_identity_verifier/binding 接线仍在，静态检查通过；请主代理核对最终 diff，不能把该文件整份 git diff 都计为本代理变更。
