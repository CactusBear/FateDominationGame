# 服务端角色与纯信令隔离：修改前说明

本批只修改 server_cli.gd、server_bootstrap.gd、server.cfg、project.godot 的相关说明及服务端 export_presets.cfg；不改 gateway/manager/worker/identity/effect/UI，不启动 Godot、不接触凭证、不提交 git。

已确认根项目有 GameData、LoadGame、EffectManager 等 autoload，切换场景或设置 rules_authority_started=false 并不能卸载它们。因此根项目拒绝 relay-only 配置和 --server-signaling；纯信令只能在没有 autoload 的独立项目运行。交付 scratch 内最小无规则项目模板及接线方案，不声称正式独立包已交付。

具体代码：网关由立即构造改为通过配置角色检查后构造；配置读取、顶层白名单与 roles 归一化复用 bootstrap 静态函数，JSON/CFG 同样拒绝未知段、未知字段以及嵌套覆盖；信令入口再限制信令字段，不接受游戏数据、身份库、权威/恢复策略。信令启动前检查 ProjectSettings 中整个 autoload 段，拒绝伪装隔离；去除没有进程观测依据的 rules_authority_started 诊断布尔值。网关策略保持复用 server_policy_config.validate，与 CFG 的 dedicated/true/reject/host_select 对照检查。根项目说明服务端 feature 只选启动场景，不隔离 autoload；Linux 与 Windows 服务端 console wrapper 均显式配置为始终导出，信号适配入口仍共用 create/enable/take_request/disable。

静态交付：新增 Python 源码契约与 JSON/CFG 配置反例检查（不模拟 Godot 规则、不冒充 GDScript 执行），涵盖角色冲突、空/重复/未知角色、未知字段/段、游戏策略注入纯信令、根 autoload 隔离闸、延迟网关构造和两平台导出参数；使用 gdtoolkit（若已安装）解析受改 GDScript。运行验收留给主代理串行执行。
