# 交接与最小接线

## 已落实
- 根游戏项目 relay-only 配置拒绝，拒绝发生在游戏网关构造前。根项目 autoload 仍然存在，**此拒绝不是根项目运行时未加载规则的证明**。
- --server-signaling 在含任意 autoload 的项目中拒绝；无 autoload 独立项目可复用信令启动逻辑。去掉 `rules_authority_started=false` 的伪隔离声明。
- JSON/CFG 读取、未知顶层字段、roles/旧开关冲突均复用 bootstrap；CFG 未知段和 server 内 data/relay 覆盖都拒绝。纯信令字段白名单进一步禁止游戏、身份、审计、恢复与管理配置进入。
- server_policy_config 已有四项策略与 CFG 一致（dedicated、true、reject、host_select），本批保留其唯一校验入口，新增静态对照而不复制策略实现。
- Linux/Windows 服务端导出 console wrapper 均声明为 2；同一 bootstrap 保留 `--` 后用户参数，两平台共用信号 create/enable/take_request/disable。重复或同时指定职责参数拒绝。

不复制根 project.godot、任何 autoload、game/session/worker/data/UI 或根服务端的 all_resources 导出预设。独立项目的导出预设使用该有限资源集合、x86_64、对应平台信号库和显式 console wrapper=2；不要宣称 dedicated_server feature 能卸载 autoload。

启动参数两平台一致：`--headless -- --server-signaling --config <本机 signaling.cfg>`；Windows 使用实际生成的 console wrapper。没有 --server-signaling 不会自动成为纯信令。纯信令不提供游戏控制台/关服保存命令，信号请求只关闭信令并退出，不影响已经建立的游戏直连。
