# 延迟事实的事务边界

现状：EventJournal.record 立即保存并发 recorded 信号，GameLog.observe_facts 用 CONNECT_DEFERRED 直接把消费者排入 Godot 消息队列。检查点恢复日志数组不能取消已排队的消费者，因此同帧记录、暂停、跳过后，下一帧仍可广播旧事实。

实施：保持 EventJournal 的立即存储、query 和 recorded 规则信号不变。在 GameLog 的展示订阅入口引入独立 FactDelivery 原语，消费者不再直接挂延迟信号；记录展示票据时复制事实与订阅身份，记录单调递增会话 generation 和当前未提交根事务 generation。延迟调度只调用原语自己的 drain，drain 检查会话与 commit 状态后再同步调用展示消费者。未提交事实保留至根事务 commit，abort 丢弃对应票据；reset 推进会话 generation，并清空旧待发布票据。每张票据先出队再调用消费者，避免重入造成重复发布；消费者退出订阅后旧票据不重新投递。

EffectManager 只在根事务建立、审计 commit 成功、回滚恢复完成、会话 reset 处推进展示边界。不新增 operation，不改变规则事实的即时可查询语义，不修改 checkpoint/match_journal、网络或 UI。多个未提交根共享对象图时展示票据依赖所有未提交根，任一回滚即作废，不将无法独立证明的部分前态展示成已提交事实。回滚恢复成功但审计完成回执失败时也立即 abort 展示 generation，保持失败关闭。

专项源码覆盖同帧 record→pause→skip→下一帧、跨帧待答与后续事实、重复 commit、abort 后新事务、会话 reset、订阅解除及重入 reset。仅执行源码静态解析与结构断言；禁止启动 Godot、读取凭证和 commit。真实 Godot 专项由主代理所有写入者退出后串行执行。
