# LAN/P2P 安全恢复 IPC v5：明确安全阻断交付

## 结论
本轮**不提供恢复成功能力**。共享恢复事务不满足失败原子性，LAN/P2P 普通 join 又没有已认证密钥绑定恢复契约；在限定文件所有权内，不能安全修复共享规则根、恢复状态持久化及控制分派。交付真实失败关闭，不能以副本、pause/resume 或进程重启冒充恢复完成。

## 已审计的恢复契约与缺口
- 已读取 hermesWarning.txt，以及 fate-domination-engine 的 authority-worker-lifecycle 恢复契约。
- `lobby_session.gd::restore_local_match` 在重放前改变 room.phase/revision 并 `_publish()`；此时原 recovery.json 可能已被覆盖。
- `_publish()` 忽略 `_persist_recovery_state()` 的布尔结果；`_commit_room_files()` 发布后，restore_local_match 无条件返回 true。重放成功不代表房间恢复状态已成功写盘。
- `match_authority.gd::restore_archive` 会切换规则数据根/驱动，并在失败路径结束规则会话，无法用外层浅字段回滚恢复完整原规则根。
- worker 的崩溃恢复虽已创建独立副本，但仍调用上述不安全共享恢复；副本只保护原对局日志，不保护原 recovery.json、房间发布状态和全局规则根。
- LAN/P2P 房主 UI 是回环客户端，不能在 UI 执行共享规则恢复。普通 join 的 gateway_identity.required=false 不能冒充密钥认证。

## 实际改动（仅本代理范围）
1. `scripts/net/session/authority_host_client.gd`
   - 新增明确拒绝的 restore_local_match 入口：不读取存档、不写 IPC、不改变 room、不关闭 transport，返回 false 并报告中文阻断原因。
   - diagnostics 显式 `archive_restore_available=false` 与机器可读阻断码，不改变 supervisor 的持续 poll。
2. `scripts/net/server/server_room_worker.gd`
   - 发现 LAN/P2P 已有 recovery.json 时，在 host、规则数据装载及旧状态加载/发布前停止启动。保留配置、恢复文件及存档，避免启动流程覆盖旧恢复事实。
   - 自动恢复入口再次先拒绝 LAN/P2P；不能扫描、复制或重放后才报阻断。此处仅记录已尝试与错误，不修改房间或规则根。
3. `scripts/net/ui/lobby_screen.gd`（对应大厅入口）
   - 有 authority_host 时走拒绝入口，显示阻断并立即返回，不回落共享规则恢复，也不显示恢复成功。

没有修改共享 lobby_session、match_authority、match_replay、server_room_control、网关、场景资源或其他代理文件。既有控制白名单 save/seed/close/pause/resume 原样保留，没有新增远程恢复消息。

## 影响与保留边界
- 新建 LAN/P2P 房间及正常网络 poll 路径不变。
- LAN/P2P 手选存档和带旧 recovery.json 的房间重启恢复明确不可用，这是有意的安全限制，不是恢复功能完成。
- 启动阻断退出尚未监听的 worker；已运行房间的手选阻断不会关闭连接或停止心跳。
- dedicated 模式旧恢复实现未修改，仍有共享恢复原子性缺口；**不得推断它已通过本轮安全验收**。
- UI 清除本次选择值，与旧逻辑一致；原档文件不改。此次失败不设置 client.error，以免污染进程监督的致命错误状态，错误放在 session.error。
- 源码静态证据不能证明 Godot 运行行为、目录 ACL 或同权限本机竞态安全。

禁止项全部遵守：未启动 Godot，未使用凭证，未 commit。无 IPC 运行成功声明，无完整恢复成功声明。

## 下一步：实施顺序与开通门槛（主代理取得共享文件所有权后执行）
1. 先在共享规则恢复链建立 prepare/commit 单一事务入口，不是另开目录轮询器：prepare 在私有工作目录复核 source 位于 worker.archive_root，拒绝设备别名、点段、ADS、链接，预算内建立随机副本；逐文件哈希、日志链、完整检查点、已认证 member-key 绑定与全部真人连接验证都在发布前完成。
2. 隔离重放期间的全局规则根与运行快照：失败必须回到完整原根，不能调用 GameStart.end_session 后仅恢复路径字符串；必要时用现有完整检查点或独立准备 worker，但不得以重启当回滚。
3. 在私有目录暂存新恢复状态、审计和续写档。单个确定的持久化提交点前，不能修改原 recovery.json、原档、room/revision、数据清单或公开视图；所有 write/flush/rename 失败必须返回 false。多个文件提交要有事务标记/提交目录指针及崩溃后确定性恢复，不能声称多次 rename 天然跨文件原子。
4. 新增**唯一**本机管理 action `restore_archive`（建议字段 room/pid/instance/authority_host_mode/action/source/request_id），同时更新 server_room_control 与相关协议白名单，严格字段集合、大小预算和请求序号；本机来源由受保护 control 目录/主管配置保证，不信任 payload 的 local=true 或随机 instance 自证权限。绑定 worker 实例和当前已认证房主，状态不符、旧 PID、旧 instance、错误 mode 必须在读档前拒绝。
5. 长时间 prepare 期间维护现有 transport 与 supervisor 心跳；阻止竞争管理与规则提交，允许身份/成员变化被检测并使事务失效；不得重入同一恢复动作或把管理 close 当作成功恢复。超时仅返回 pending/未知，不能猜成功或杀进程。
6. 客户端仅在读取同一 request_id、room、pid、instance、mode 的持久化提交回执并核对 worker 的已提交事务状态后显示成功；拒绝无回执、过期回执和只写临时状态的回执。
7. 先增加失败注入测试：错误绑定/远端来源/越根/链接/损坏日志/数据哈希不匹配/真人不齐/写入与 flush 失败/提交 rename 失败/重放中房主变化/worker 崩溃/回执丢失。每个反例验证原档、recovery.json、规则根、room 修订、公开快照与 transport 不变或明确未提交。新生产 IPC 通过后，才能删除本轮阻断。
8. 所有写入者退出后主代理串行 Godot 验收，复用现有 `tests/net_recovery_state_test.tscn`、`tests/recovery_path_safety_test.tscn`、`tests/net_server_recovery_match_test.tscn`，并补 LAN/P2P 管理 IPC 专项。旧专项通过不能代替新增 IPC 失败注入及真实窗口入口。

主代理开通前可先重新执行上述静态命令；当前阻断状态是预期结果。
