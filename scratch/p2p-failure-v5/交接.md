# P2P 信令失败 v5：源码反例与验收边界

## 修改范围
仅 `scripts/net/p2p/p2p_signal_client.gd`、`p2p_signal_server.gd`、`p2p_invite.gd`。没有改传输层、对局协议、规则权威或添加 TURN。此目录中的 `before/*.gd.txt` 是改动前真实源码快照，使用 `.txt` 防止 Godot 注册重复全局类。

## 源码反例（事件序列，不是已执行网络测试）

| 反例输入 / 时序 | 旧源码可见结果 | 修复后的源码控制流 |
|---|---|---|
| 房主正在 gather/等 answer，WebSocket CLOSED | CLOSED 分支直接 return，pending 永不经过超时循环 | 统一 `_fail_signaling` 取消未连通 peer、清空 pending、释放信令 socket |
| answer 已消费，但 ICE 仍 CONNECTING，然后信令断开 | answer 分支提前 erase；invite.cancel_offer 又拒绝 consumed，未连接 peer 逃过清理 | answer 只标 answered；保留 deadline；cancel 仅保护 STATE_CONNECTED |
| 客机正在初连/恢复，信令断开、超时或 send 失败 | 初连无共同清理；恢复的 warn 有隐式关闭，非致命警告也影响握手 | 显式失败入口关闭未连通 guest transport/invite；恢复调用 fail_reconnect；warn 仅通知 |
| 已有直连对局，信令关闭或 room_closed | 旧部分分支只告警，其他关闭逻辑不统一 | 失败清理不调用整个 client.close；客机已连通不关闭 transport；房主只取消未连通邀请 |
| create 的 send_text 返回非 OK | 房间、host、expires 已登记，created 未送出 | 先检查发送返回码，失败移除信令客户端；没有登记房间 |
| join 的 join_request 发送返回非 OK | guest.room/deadline 已登记，房主没收到请求 | 先检查发送返回码，失败移除 guest；没有登记加入状态 |
| 32 条在 999ms，32 条在 1000ms | 整秒桶重置使后一批仍获额度 | 时间戳滚动窗口；前一批在 1000ms 尚未过期；超额度关闭来源连接 |
| 最早消息在 t，下一条在 t+999 / t+1000 | 固定秒桶取决于全局秒边界 | 保留 `(now-1000, now]` 内记录；恰好 1000ms 旧记录过期（半开区间） |
| SDP 内 `a=candidate:... typ\trelay` 或多空格 `typ  relay` | 仅搜索 `typ relay`，可以绕过 invite 的子串检查 | 分行、规范化 tab 后调用既有 direct_candidate；只接受 host/srflx/prflx |
| 配置包含 turn:/turns:、credential、非 iceServers 字段 | 现有 webrtc_link 配置白名单本来拒绝 | 保留原配置检查，不加入 TURN 或回退转发 |
| 同一客户端重复 join_request、offer、answer；成功后重复 join_request | 待握手阶段有防重；成功后 pending 已 erase，可能再次分配 peer | pending 防重 + 活跃客户端到 peer 的对应表；offer 忽略重复；answer answered/nonce/consumed 防重 |
| accept_answer 设置 remote description 成功，但某 candidate 加入失败 | 部分应用连接残留；再试可能受已设置描述状态影响 | accept_answer 失败移除该 peer 和对应 invite pending，不回滚成可重放握手 |
| offer 创建底层连接后 create_offer 失败 | invite pending erase，但底层连接可能残留 | 清理 link.remove_peer 后 erase |
| 服务端 _handle 因发送失败移除当前 id，但同一 socket 还有队列消息 | 原消息循环可能继续引用已删除客户端 | 每次 handle 后检查 id 仍存在，不存在则 break |

## 源码可证 / 静态验证范围

- `verify_static.py` 是源码结构断言，不是 Python 重写网络模型，不会运行 Godot。
- `static-before.json`：原始 10 项断言中 9 项失败、0 个错误，证明能识别旧结构缺口。`static-duplicate-before.json`：追加成功后重复握手断言时 11 项中 1 项失败、0 个错误。
- 三个生产文件在当前工作树均为未跟踪文件，`git diff --check` 不覆盖它们；已另外用 `audit_changed.py` 对比真实改动前快照，生成 `changes.patch`、`diff-results.json`，检查所有新增行无尾随空白。
- 最终计数以 `static-results.json` 为准；第三方语法解析结果在 `parser-results.json`。gdtoolkit 只检查语法，不检查 Godot 的静态类型、native API 和 WebRTC 扩展。
- 服务端登记成功仍以 WebSocket send 返回 OK 为边界：OK 只代表本地队列接纳，不承诺远端已收到；随后断线由既有 remove 生命周期处理。
- relay 仍仅交换 create/join/offer/answer，不承载游戏数据、不启动规则权威、不提供 TURN。

## Godot 运行 / 公网实测必需（本子代理禁止执行）

1. 主代理串行执行受影响 Godot P2P 专项，检查脚本静态类型、WebRTC native API/扩展、错误日志；本目录静态全绿不能替代。
2. 注入 send_text 返回失败，分别检查 create 无房间登记、join 无客机登记；发送 OK 后立刻断线也需验证实际生命周期。
3. 房主同时拥有已连接客机和 gathering/已答但未连接客机，在信令 disconnect/room_closed/超时处分阶段注入故障，验证已连通链路持续收发、其余连接被移除；客机初连和恢复均覆盖。
4. 双机异网实际测 NAT/STUN：双方 NAT 类型、selected candidate pair、候选类型、双方稳定数据收发及信令断开后的直连保持。对称 NAT 等无法直连时必须明确失败，不转发兜底。
5. 按秒边界突发、恰好 1000ms 窗口、队列积压、重复握手、部分 SDP 应用失败做实际输入；验证 relay 不接受游戏消息、TURN/relay 候选不可用。
