# 最终剩余代码缺口审计

## 范围与结论

- 本审计只读取当前生产源码和文档，只写本文件；未启动 Godot、服务端、导出程序，未读取身份库或凭证。下列都是静态结论，不是运行验收。
- 优先级定义：P0 为数据安全/恢复主链及确定的生命周期缺陷；P1 为已定方案能力补齐与发布前必要接线；P2 为运维完善与事实清单收敛。这里的 P0/P1/P2 是剩余任务优先级，不是原方案实施阶段编号。
- 主代理可直接推进这些代码与测试夹具，不必再询问已经确认的权威位置、身份绑定、继承或完整根事务回滚口径。真实包导出仍须用户授权；多机、公网和目标系统现场验收不能由静态审计代替。
- 当前拓扑：信令 WebSocket 交换握手信息；LAN/P2P 数据经房主直连入口再路由到房主机器上的 room worker；独立服务端由网关路由到服务端机器上的 room worker。规则不在 UI 客机执行，信令节点不转发对局流量。不能用旧的同进程房主测试证据证明新子进程入口完整交付。

## P0：先处理

### P0-1 恢复状态/房间配置覆盖写入仍缺 Windows 失败原子性

**静态确认**：`scripts/net/session/lobby_session.gd:1351-1367` 的 `_persist_recovery_state()` 和 `scripts/net/server/server_room_manager.gd:108-119` 的 `write_configuration()` 均以临时文件加 `DirAccess.rename_absolute()` 覆盖旧目标。临时写入检查不等于 Windows 覆盖替换安全；现有 `scripts/net/identity/legacy_identity_migration.gd:71-109` 已明确处理该平台问题，使用原生原子替换并保留原字节。

**直接任务**：先提取/复用本机可信路径的安全替换能力，迁移恢复状态与配置覆盖入口；首次新建和覆盖旧文件分别处理，不能只删掉显式 remove。写盘失败应保留旧目标和旧内存绑定/暂停/密码状态，不发布成功回执或新票据。

**验收**：已有目标替换失败、权限拒绝、flush 失败、源文件被并发更改、首次创建失败；逐字节核对旧档不变，再覆盖保存、密码设置、暂停、身份继承和 recover_room 的调用链。

### P0-2 LAN/P2P 密钥身份及房主存档恢复尚未贯通

**静态确认**：`authority_host_client.gd:61` 给本机房主的 join 显式传入 `gateway_identity.required=false`；大厅 `_host/_join` 只对独立服务端模式执行 `_prepare_identity()`（`lobby_screen.gd:339-341,417-419`）。`authority_host_client.gd:102-117` 的恢复入口固定拒绝并报告 `archive_restore_available=false`；`server_room_worker.gd:85-90` 遇 LAN/P2P 旧恢复状态直接拒绝启动。现有安全阻断是正确边界，不是已实现恢复。

**直接任务**：复用现有身份密钥挑战/认证与成员绑定模块，让 LAN/P2P 房主和客机取得真实认证上下文，不能通过载荷自报 key 或 required 字段认领；再在房主机器 worker 建立候选恢复→完整校验→原子提交→素材屏障的实例绑定控制链，接回本机存档菜单与崩溃后原房间登记。共享 `LobbySession.restore_local_match()` 当前先发布 restoring、重放后再发布素材（1369-1421），须先修失败原子语义，不能直接取消阻断。

**依赖/验收**：先完成 P0-1。覆盖错误密钥先拒绝、缺旧绑定保留原档、房主选择稳定 member_id 继承、昵称重复、写盘失败不换状态、保存后房主进程崩溃、原真人重连、数据确认后继续同一中局。LAN/P2P 分开测；现有 dedicated 恢复通过不代表这两类已通过。

### P0-3 本机权威安全关闭回执匹配使用已清空 room_id

**静态确认**：`authority_host_client.close()` 保存 `_closing_target` 后于第 138 行把 `room_id` 清空；随后 `_drain_close()` 第 152 行仍以 `response.room != room_id` 过滤回执。正常关闭回执带真实房间 ID，因此会被忽略，关闭被拒的警告不能按预期发出。

**直接任务**：使用保存的关闭实例绑定校验 room/PID/instance/mode，并保存请求编号；明确处理提交失败、拒绝回执、成功回执后真实退出、重复 close 和退出 UI 后排空的生命周期。不能因超时强杀未保存 worker，也不能把 IPC 写入当退出完成。

**验收**：房间已录制可关闭、未录制拒绝、提交写盘失败、旧实例/旧请求回执、连续两次 close、另一个房间保持在线。确保场景退出后拒绝原因可观察且监督不误操作其他实例。

### P0-4 ENet 房间口令仍明文传输且缺专用猜测预算

**静态确认**：`lobby_session.gd:388,719-724` 把原口令放在 join/room_password 消息；`enet_transport.gd:35-60` 创建普通 ENet peer，没有加密接线。`room_password.gd:13-26` 是随机盐 SHA-256，不是抗离线穷举 KDF。已有身份尝试限流在 gateway，不等于房间口令猜测限流。待确认清单第 48 行明确保留这些安全缺口。

**直接任务**：先补房间加入口令的独立次数/时间预算（跨重连不能轻易归零，避免一人耗尽全服预算），固定拒绝语义和脱敏；再为 ENet 的口令与私有恢复凭据设计并接线经过认证的保密通道/成熟安全协议，复用原生能力而不自造加密算法。存储格式支持版本化 KDF 与旧验证值的明确迁移，不能只换哈希就宣称网络安全。

**验收**：多连接猜测、重连绕过、合法成员恢复不被误封、错误口令不加入、密码/票据不进公开快照与日志；抓取实际 ENet 流量验证无原文。WebRTC 加密不能证明 ENet 安全。

## P1：能力补齐与发布必要接线

### P1-1 真正的对局硬超时仍需与完整恢复检查点一起实现

**静态确认范围**：`room_validation_task.gd` 有预检子进程硬超时；room worker 的 supervisor 心跳检查在 `_process()`（205-216），与规则同线程。单个同步原生 op 卡住时不能靠该 worker 主循环自救。`rule_checkpoint.gd:3` 明确只同进程恢复对象；进程重启不是根事务回滚。

**直接任务**：梳理 worker 可观察的运行进度，接外部 watchdog 的安全失联判据；先建立跨进程可验证的完整事务起点/恢复契约，再允许硬中断后的恢复或跳过。未建立时只支持疑似异常、暂停/最近完整档恢复/重开并如实报告能力，不把 kill+restart 显示为 rollback。避免把玩家等待、管理员暂停或网络下载算成规则执行耗时。

**验收**：真实不可协作 op 挂起、长但合法计算、待答不超时、主管仍响应、旧实例被拒；中断后逐项核对根事务前态和审计边界。预检超时测试不能代替真人对局硬超时测试。

### P1-2 根事务回滚支持范围与原生副作用矩阵仍需补完

**静态确认**：`rule_checkpoint.gd:95-127` 拒绝未声明 Node、不可采集内建对象、RID、PackedArray；`effect_checkpoint.gd:50-61` 手工列出静态池并排除运行保护字段。现有父子待答/延迟尾部支持不能自然覆盖所有 operation 的外部副作用和所有 static 状态。

**直接任务**：按实际 operation、原生返回值消费者和静态写入盘点支持矩阵；补只读/失败关闭的能力声明及红反例。只对实际需要的类型增加完整别名/生命周期契约；不可撤销的文件/进程/其他外部副作用要明确禁止 rollback 或建立独立提交边界，不放宽拒绝来换按钮可用。

**验收**：资源、对象身份/牌序、队列/待答/计次、随机、日志边界、外部尾部一次性与恢复失败前态；每个新支持类型独立红转绿。对应 open-questions:38,43 的已定要求。

### P1-3 权威隔离后的大厅录制控制与存档状态显示脱节

**静态确认**：大厅把 Record.toggled 仅赋给 `session.record_matches`（`lobby_screen.gd:63-64`）；`authority_host_client.start():34` 在创建 worker 前只复制一次该开关。后续房主 UI 是客户端（LobbySession.close 将 `_host=false`，host_authority 不再调用 _initialize_host），但 Archives 的可见性和按钮资格仍按 `session._host`（498-500）判断。恢复能力又固定 unavailable，UI 不能继续沿用旧同进程主机资格。

**直接任务**：区分“房主管理资格”和“本进程规则权威”，按真实权威回执展示录制开关/目录/可恢复能力。若只允许建房前固定录制则显式冻结控件；若允许大厅修改则通过实例绑定管理请求修改 worker 并回读，失败保持旧配置。不能改 UI 本地变量冒充 worker 已开启录制。

**验收**：建房前开关、建房后修改/拒绝、转让房主管理权、实际日志产生、隔离恢复不可用提示。P0-2 完成后另验正式恢复按钮，不回退 UI 规则执行。

### P1-4 客户端导出预设未同步临时资源隔离

**静态确认**：`export_presets.cfg:15,86` 两个普通客户端预设仍仅排除 `data/*`；服务端预设第 132、153 行已排除 `scratch/*`、tests/reports/docs 与 Git 插件。Linux 客户端采用 all_resources，不能只修服务端后认为发布阻断全消失。

**直接任务**：给正式客户端预设补临时资源/测试/报告/编辑器专用插件隔离，核对客户端必需 WebRTC 与外置 data 复制能力不被误删；审查根备份和工具资源。新增服务端/客户端的共同过滤断言及预检，不为清零而删正常插件。

**验收**：先静态验证每个预设；授权导出后检查真实 PCK 清单、库和外置 data，不能只检 CFG 文本。

### P1-5 建房前预设密码没有进入权威创建事务

**静态确认**：`lobby_screen._host():355-385` 各模式只传 settings，现有 RoomPassword.Input 仅在 `_join()` 赋给 join_password；gateway 的 server_create 把 name/settings 交给 manager。房间首次默认无密码，房主入大厅后才可设置，符合当前文档边界但不构成建房即受保护。

**直接任务**：把创建前预设与加入密码语义分开，创建请求中显式传递受保护的初始化值，在 worker 接受其他成员之前设置并确认；创建失败保留配置/凭据安全，不把口令写进普通 settings、命令行或快照。先完成 P0-4 的传输保护。

**验收**：新房首个外来 join 抢跑、空密码取消语义、设置失败不开放无保护房间、LAN/P2P/dedicated 分模式验证。若本批不实现，UI 明确说明“进入大厅后设置”，不得展示为预填即保护。
