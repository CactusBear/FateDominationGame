# P2P/relay 权威位置边界：修改前说明

本代理只修改 p2p_signal_client.gd、p2p_signal_server.gd；必要时 enet_transport.gd（当前没有发现其明确缺陷，不改），新增独立专项及诊断/公网验收夹具。保持当前未提交修改；不运行 Godot、不读取凭证、不 commit。

## 已读与发现
- 已读取 hermesWarning、技能 multiplayer-architecture、docs/multiplayer-p2p-progress、邀请码与 WebRTC link。webrtc_native.gd 不存在，实际实现是 webrtc_link.gd（只读）。
- 现有 WebRTC 只允许 STUN 配置，拒绝 TURN 与 relay candidate；信令服务仅 create/join/offer/answer，已有真实房间、nonce 和目标绑定。没有游戏转发路径。
- 信令客机尚未校验回复字段白名单，重复 created/offer 会再次触发初始化；发送返回值被忽略，失败仍设置 sent 标记。客机握手前信令断开时提示“已建立直连不受影响”，错误暗示已有连接。
- P2P/LAN 当前会话在房主进程内运算，没有新的隔离规则子进程接线；独立服务端由 server_room_manager 在服务端机器启动 worker。隔离 worker 由兄弟代理负责，本代理不越界。

## 本批逐项代码解释
1. 客机新增只读 authority_host_mode=p2p_host_machine 与 diagnostics()，显式表明期望的权威机器，不推导实际 worker PID。诊断仅报告真实信令状态、已收应答/待握手数、直连传输状态；NAT 类型和 selected pair 保持未测，不收集 IP/SDP/密钥。公网验收状态保持未验收。
2. 客机 _receive 对 created/join_request/offer/answer/error/room_closed 校验完整字段及类型，拒绝游戏包与额外数据；重复 created/offer 原子拒绝，不重置既有直连。单独 _received_offer 标记成功接入才设为 true，close 清理。
3. _send 返回 Error，按实际 UTF-8 消息预算校验，处理真实 WebSocket send_text 返回码；create/offer/answer 只有成功入队才修改 sent 状态。失败显式提示且不谎报已发。
4. _open 复用 WebRTC 现有 _direct_configuration 验证（在客机等待 offer 前就拒绝 TURN），检查时间换算溢出。信令断开文案按真实直连状态分支，绝不关闭已有游戏通道。
5. 服务端补 diagnostics()：authority_host_mode=disabled_on_relay、game_forwarding=false，列信令数量而非 WebRTC 连接成功；服务端未知游戏包维持原拒绝路径、发送检查大小与返回码；复用 configure({}) 在 listen 前验证包括 TTL/码长在内的现有字段，不部分应用配置。
6. 新独立 GDScript 反例专项覆盖 relay 游戏消息拒绝、TURN/relay候选拒绝、重复信令不重建；仅写源码不运行。新增公网证据模板与验收文档，要求真实跨网、权威 PID/机器、关闭信令后的双向业务流量、无 TURN/relay 证据；未知 NAT 不阻止连接，失败明确记录而不降级转发。
7. 用 gdtoolkit 静态解析及 git diff --check，记录为静态证据，不升级为 Godot/公网通过。
