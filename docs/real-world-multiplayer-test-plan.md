# 真人单机多进程与观战验收 v5

## 结论边界

本文件是待执行的真人任务，不是测试通过报告。当前所有用例为 `NOT_RUN`；本次编写未启动 Godot。必须非 headless 真实窗口、真人鼠标键盘输入并提供截图/录屏、权威日志和状态对照。静态解析、单元测试、直接调用规则 API、窗口仅出现、SERVER_ROOM_READY 均不能替代真人通过。

范围：同一 Windows 机器 H（房主）、G（客机）、S（观战）、X（额外负测/中途观战）四个独立进程；默认 AI=0。至少一名真人依次操作各窗，推荐两人分管H/G、第三人观战与记录。一次只执行一个破坏性用例。单机回环不证明真实跨机LAN/NAT/P2P；不提供外网凭证、不提交 commit、不改生产数据。

## 启动与隔离（由真人执行）

原项目 `project.godot` 使用同一 `FateDomination` 用户目录；直接起四次会共享身份、缓存及存档，不能用于身份验收。准备脚本只复制测试项目并修改副本的用户目录，不运行 Godot、不接触原用户身份文件。默认输出在 Hermes scratch 的唯一运行目录；需足够磁盘空间，副本不采用符号链接/硬链接。

在 PowerShell 中执行（注意不是 Git Bash）：

```powershell
Set-Location E:/Projects/Godot/FateDominationGame-master
& ./tests/real_world_acceptance_v5/prepare.ps1
# 输出 RunRoot 与 launch.ps1 路径；检查后再执行输出目录的 launch.ps1。
# launch.ps1 才会启动真实窗口；准备脚本本身绝不启动引擎。
```

复制输出目录中的 `run-template.json` 为 `run.json`，填操作者、机器/系统、提交号及工作树说明、Godot版本（读取真实工具输出）、窗口尺寸/缩放、测试模式、端口、开始时间、数据清单和角色PID；复制 `checklist.csv` 作为本轮结果。首次副本导入失败时由真人用同一引擎打开副本编辑器完成导入，关闭编辑器后再跑；不能把导入错误算玩法通过。H默认从开场主菜单进入联机，G/S/X直接进入现有联机大厅；记录菜单找不到入口或大厅控制被裁切，不能用直接场景绕过H的失败。

各窗用户名分别 `rw_host_v5`、`rw_guest_v5`、`rw_watch_v5`、`rw_extra_v5`，昵称分别房主甲、客机乙、观战丙、额外丁；重复昵称用例临时改昵称。房间密码由真人在本地选择和输入，报告仅记 empty/wrong/correct，不得记明文。`user://` 在每个副本配置为 `FateDomination-RWv5-<run_id>-<role>`，用实际解析位置作记录，不猜原用户数据路径。

启动后先映射房间权威子进程PID/room_id/instance_id及日志实际位置；进程必须按PID单独操作，禁止按Godot进程名全杀。进程断线、主动离开、管理房主转移、权威迁移、进程重启、大厅恢复、原局恢复是不同结果。

### 独立服务端前置

RW03/RW17–19及认证分支必须额外有隔离认证服务端；LAN成功不补这部分。下面命令由真人执行，仍不加 `--headless`；先由现有CLI生成配置，检查并配置隔离 data_root/storage_root/console_dir 和仅本机监听，再重新启动：

```powershell
$Godot = 'D:/Godot4/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe'
# 使用 prepare 输出的 V 项目副本及 RunRoot；不存在的 .cfg 第一次只生成配置并退出。
& $Godot --path "$RunRoot/projects/V" --log-file "$RunRoot/logs/V-config.log" --scene res://assets/scenes/main_menu/server_cli.tscn -- --server-gateway --config "$RunRoot/server.cfg"
# 检查配置后使用新的 V-gateway.log 启动，不复用旧就绪日志。
& $Godot --path "$RunRoot/projects/V" --log-file "$RunRoot/logs/V-gateway.log" --scene res://assets/scenes/main_menu/server_cli.tscn -- --server-gateway --config "$RunRoot/server.cfg"
```

引擎路径由prepare实际检查；若安装文件名不同显式传 `-Godot`。管理员先读实际 `help`，将房间恢复/保存关闭命令原文写入 run.json，不猜命令格式。本轮必须记录authority_host_mode，服务端权威工作在本机服务端而不是信令进程。没有认证服务端或安全负测夹具记BLOCKED，不扩大任务去部署公网服务或读取凭证。内部规则工作进程由产品启动模式决定，但所有参与验收的客户端必须真实窗口。

## 执行与证据规则

1. 每个用例先记录前置（房间、相位、数据修订、完整检查点、三个角色）、开始时间，再真人操作；含多分支的用例每个分支独立记录结果。
2. 每次动作至少保存操作者的画面、其他两端的公开状态及权威原始日志片段（带文件与行号/时间），缺日志则标 `evidence_gap`，不得编造事件名。日志中的下述事件名称仅是检索线索，只有实际出现才引用。
3. 每个破坏性用例另起日志和存档，保存动作前后状态/文件哈希。连续录屏需能辨认角色窗口、输入和时间；截图单独不能证明顺序、无重复扣费或回退。
4. 状态只能为 NOT_RUN / PASS / FAIL / BLOCKED；PASS须全部步骤和预期完成、真实窗及真人输入得到记录、每分支证据齐全、复核签名。缺入口/数据/环境可BLOCKED；预期与实际冲突FAIL；阻塞、未执行均不计通过。
5. 失败先停止推进并记录最后成功步骤；复制白名单日志、存档公开/脱敏片段、录屏与测试数据清单。不得打包整个user目录、private.pem、profile内敏感内容、恢复票据或房间密码。隐藏牌私有画面仅受限存储。原始日志可能含敏感字段，应先本地审查和脱敏再共享。

## 逐项清单

基础路径先RW01–12；恢复分支用独立房间RW13–19；异常分支RW20–22；保存关闭RW23–24。失败后只继续不依赖该前置的用例。

### RW01 真实窗口与隔离
- 前置/模式：基础。
- 操作：运行准备脚本；分别打开 H/G/S/X 四个真实窗口，H 从默认开场经主菜单进入联机，G/S 可直接大厅；检查窗口、PID、日志和用户目录。
- 预期：四个独立进程、身份和缓存目录；真人能用鼠标键盘操作；主菜单入口可达。
- 日志与画面证据：四窗截图或录屏；PID/角色/启动命令映射；每角色本次日志。
- 失败收集：窗口缺失、控件被挤出屏幕或共用身份目录立即阻断后续，记录分辨率、缩放和错误。

### RW02 身份合法输入与边界
- 前置/模式：基础+认证。
- 操作：H/G/S 输入各自测试用户名和昵称；依次测试空、数字开头、中文、空格、短横线，再测试32字符与粘贴33字符；独立服务端登记合法身份。
- 预期：合法为英文字母/下划线/数字、首字符非数字、最多32字符；非法不得连接；33字符截断或拒绝行为明确记录，不能产生超长身份。
- 日志与画面证据：身份提示截图；登记前后大厅状态；服务端登记响应或日志。
- 失败收集：保存输入类别与提示，不能收集私钥或密码；缺服务端时登记结果记BLOCKED。

### RW03 重复昵称与用户名唯一
- 前置/模式：认证。
- 操作：G/S 设同一昵称、不同用户名加入；X 用自己的新身份登记 G 的用户名；再测试仅大小写不同用户名。
- 预期：昵称可重复且以用户名消歧；重复用户名拒绝；用户名区分大小写；UI 不显示密钥、指纹或票据。
- 日志与画面证据：同昵称成员列表截图；重复登记拒绝截图与脱敏服务端响应。
- 失败收集：登记后查询实际成员，记录是否覆盖身份或占错席位；若出现敏感标识停止传播截图。

### RW04 建房加入与观战角色
- 前置/模式：局域网。
- 操作：H 选局域网、监听127.0.0.1、端口24680、AI=0创建；G 以玩家加入；S 勾观战加入；选模式时记录真人席位容量。
- 预期：三端同一房间；H房主、G玩家、S观战；观战不占玩家席位、不参与准备门槛；规则权威在房主机器。
- 日志与画面证据：成员表、设置、角色截图；H权威子进程PID和日志；加入响应。
- 失败收集：记录实际绑定地址、端口、角色与容量，不以同机成功推断跨机网络成功。

### RW05 房间密码正反例
- 前置/模式：基础+认证。
- 操作：新房默认无密码加入一次；H大厅设置测试密码，X空密码/错误密码/正确密码分别加入；G尝试修改；H清空后X再加入；重新设密码用于后续。
- 预期：默认无密码；错误拒绝且成员列表不增加；正确可加入；仅房主大厅可修改；清空取消；密码字段掩码。
- 日志与画面证据：密码状态而非内容截图；每次拒绝与加入日志；成员前后对照。
- 失败收集：只写password_case=empty/wrong/correct；任何日志泄漏密码标安全失败，原件本地隔离。

### RW06 数据选择与同步屏障
- 前置/模式：基础。
- 操作：H点房间数据，按玩家与条目选择H/G来源、保留一项、排除一项，确认依赖；G/S点同步数据；同步中尝试准备和开始；完成后再准备。
- 预期：只有明确批准的条目及声明依赖进入房间；权威清单一致；未确认当前数据修订的成员不能越过屏障；观战也同步公开资产。
- 日志与画面证据：批准条目清单、修订、文件摘要；同步进度/完成截图；权威校验日志及data_ack响应（若输出）。
- 失败收集：保存缺文件、依赖、摘要和拒绝原因；日志未暴露修订时标证据缺口，不能编造data_ack成功。

### RW07 同名数据冲突与缓存
- 前置/模式：基础。
- 操作：在独立测试副本数据中准备同名不同内容条目（保留原件及哈希）；H明确选择来源后同步；再次加入检查缓存；G用清缓存按钮后重同步；H改批准清单。
- 预期：冲突由房主明确处理而非客户端覆盖；缓存默认开启、可清理；修订变化旧确认失效；牌图与条目来自房间数据而非本机同名模板。
- 日志与画面证据：条目路径/哈希/批准来源；缓存前后清单；新旧修订和对应牌图截图。
- 失败收集：不改原仓库数据；无法在UI选择来源或证明缓存命中记BLOCKED/FAIL，不以快慢当命中证据。

### RW08 选人权限与隐私
- 前置/模式：基础。
- 操作：全员同步准备；H开始选人；H/G分别按模式选择未占用御主，G尝试已占用项；S尝试选人/开始；用随机分配模式再跑一局。

- 日志与画面证据：H/G/S同期选人截图；选择成功/拒绝和分配完成日志。
- 失败收集：记录模式ID、御主和私有结果只放受限证据；出现公共隐藏名单立即失败。

- 失败收集：按player_id核对而非昵称，保留三阶段对照，无法取得ID证据记缺口。

### RW10 真人对局输入与权威

### RW12 观战隐私与中途加入

### RW17 服务端工作进程恢复原局
- 前置/模式：认证服务端。
- 操作：先完成一回合并保存；记录room_id/instance_id/权威PID/存档；只终止该房间工作进程，保留网关；管理员用help确认的房间恢复入口重启；H/G以原认证身份重连；S随后观战。
- 预期：房间登记保留；先读旧档和校验已有数据再持久化；playing重启进入restoring；所有原真人身份密钥匹配重连并过数据屏障后才恢复playing；资源/顺位/待答与档一致。
- 日志与画面证据：新旧独立工作日志；SERVER_ROOM_READY只能作就绪证据；恢复相位、逐文件校验、成员绑定及存档对照。
- 失败收集：记录恢复命令原文但脱敏票据；只恢复大厅或子进程就绪不算通过；缺服务器/命令/相位日志为BLOCKED。

### RW18 身份继承成功与受限失败
- 前置/模式：认证服务端。
- 操作：G掉线保留原席位；S保持已认证观战；当前已认证房主打开身份继承面板，按昵称/用户名选择稳定S成员，确认继承G；S完成旧观战连接关闭再重连；G再试旧恢复身份。
- 预期：只有认证房主可授权；继承绑定当前房间修订和请求序号、写审计；S恢复G原席位与归属而非新增玩家；旧凭据不能再抢占；UI无公钥/指纹/票据。
- 日志与画面证据：授权前后成员表、面板与S切换录屏；脱敏授权审计和席位绑定；旧身份拒绝。
- 失败收集：缺认证服务端不能用LAN代替；保存失败时旧档/凭据不得改变；原件不含凭据明文。

### RW19 继承拒绝与旧档失败关闭
- 前置/模式：认证服务端。
- 操作：G/X/非房主S尝试打开继承入口；房主打开面板后让成员或房间修订改变再提交；在隔离复制的恢复档缺失成员认证绑定后尝试恢复（不得改正式档）；观察持票但不同认证身份恢复是否被拒。
- 预期：非房主/过期上下文拒绝；认证密钥不匹配先拒绝；旧档缺绑定失败关闭并保留原目录/配置/存档，不让首个持票者认领。
- 日志与画面证据：权限/过期拒绝截图；旧档副本哈希；工作日志拒绝原因；授权审计未新增对照。
- 失败收集：不得为负测读取/复制真实私钥和票据；持票错身份若无安全注入夹具记BLOCKED，禁止模拟一条日志充当拒绝。

### RW20 预算配置与异常提示
- 前置/模式：基础。
- 操作：大厅分别测随机模拟关闭、开启0秒、开启小正预算；协作执行预算独立开关；在测试副本批准的已知异常效果触发预算超限，三窗观察且在预算中移动鼠标。
- 预期：0秒效果等同关闭但开关独立；计算后台进行；超限称疑似异常，弹窗含所属玩家、来源牌、具体效果；不常驻预算原因/步数；原生不可暂停区间不承诺硬时限。
- 日志与画面证据：设置与异常弹窗截图；实际卡/效果与数据摘要、预算、耗时；权威异常日志。
- 失败收集：无可安全触发异常夹具或事件入口记BLOCKED，不改生产规则、不杜撰异常弹窗；记录窗口是否失去响应。

### RW21 异常跳过完整回退
- 前置/模式：异常夹具。
- 操作：准备带前置扣费、移动、标记或连锁变化的受控异常；记录发动前完整检查点；触发后房主选择跳过，客机/观战尝试代选。
- 预期：仅授权者处理；整个效果及连锁回到发动前，资源/位置/牌区/标记/次数/待答/历史一致；缺完整可验证检查点不得伪称跳过成功，只暂停并提供安全恢复/重开/回大厅。
- 日志与画面证据：发动前、部分执行、处理后三阶段存档及三窗录屏；回退日志；逐字段比较表。
- 失败收集：保留可重现测试数据副本与哈希；发现部分状态残留立刻FAIL，冻结证据不继续推进污染现场。

### RW22 当前阵容重开与回大厅重选
- 前置/模式：异常夹具。
- 操作：另起异常轮选择按当前阵容重开；再起一轮选择回大厅重选；保存重开前阵容/顺位/身份/预算；G/S尝试处理异常。
- 预期：重开保留规定阵容与归属、不继承部分扣费/残局；回大厅允许重选；大厅预算设置保留；新对局状态与旧档隔离；客机观战不能越权。
- 日志与画面证据：两分支独立录屏及日志；阵容、ID、预算与新档对照。
- 失败收集：明确新局顺位实际规则，不把旧局复用顺位与新局重开混为一谈；缺处理入口记BLOCKED。

### RW23 保存、正常关闭与恢复
- 前置/模式：基础+认证。
- 操作：勾记录对局；完成一回合保存，记match.log目录；H/G/S按正常离开关闭，服务端用实际保存关闭入口；重新启动，H用恢复存档选择match.log并确认，原真人重连同步。
- 预期：权威机器保存完整档；成功保存才关闭；凭据明文不落恢复档；原档不被空状态覆盖；恢复复制原档并验证数据，继续行动不重复扣费；客户端不能冒充权威存档。
- 日志与画面证据：保存确认和退出日志；match.log与相关清单哈希；恢复前后截图、权威状态；本轮实际退出码。
- 失败收集：关闭即退出无保存保证则FAIL/BLOCKED并注明；不把日志文件存在等同保存完成，禁止打包私钥及恢复票据。

### RW24 保存失败与失败现场收集
- 前置/模式：基础+认证。
- 操作：仅在隔离测试存储目录通过可恢复权限/只读方式制造保存失败；触发保存关闭/继承保存，观察是否保留旧档；恢复权限后再试；最后整理全部结果。
- 预期：保存失败明确反馈、不能假报成功或覆盖旧档/凭据；旧档保留；证据齐全才PASS；阻塞与未执行不可算通过。
- 日志与画面证据：错误截图、旧档前后哈希及保存响应；恢复权限步骤；本轮结果、问题单和脱敏证据索引。
- 失败收集：记录ACL/权限改动及还原，不能改正式存储；不收集整份user目录；失败冻结现场后复制白名单证据。
