# 文件校验多线程

原实现为独立校验进程内部串行。RoomDataValidator现使用WorkerThreadPool并行文件读取、SHA256和纯JSON解析，默认file_worker_count=4，设1走同代码串行对照。

线程任务各持独立FileAccess及JSON解析器，只读取本轮复制后的清单；结果数组预分配，写入受Mutex保护，等待全部完成后按原清单顺序汇总。AllOperations/BoardPowerQuery引用校验、场景加载和模拟仍在调用线程，不能并发操作全局规则状态。非法线程预算拒绝，不绕过原校验。

实测：同一205文件、同代码、三对交替暖缓存，中位数串行255.055ms、四线程108.748ms，约2.35倍，只代表初始文件校验阶段，不代表素材准备/场景加载/试运行全链。

验证：实际工作线程ID与调用线程不同；正确文件通过，错哈希、错长度拒绝，错误顺序与串行一致，非法预算拒绝，专项7项通过。原I/O反例套件通过。独立完整加载及固定种子试运行返回ok=true/errors=[]、7御主8从者。真实后台校验、下载、准备、五AI选人进入战局22项通过。

首次完整流程探针因传入原生反斜杠report路径被既有路径检查拒绝；改用规范正斜杠本机路径后通过，没有放宽路径安全策略。

当前v7发布包不含此修改，后续导出需包含多线程及后台校验变更。全部游戏测试输出位于E盘。
