# 跨网络真人 P2P 验收任务（待用户拿包实测）

## 交付状态与边界

**当前状态：待真人跨网实测，未验收。** 本文件和 `tests/real_world_acceptance_v5/cross_network_matrix.json` 只是任务与记录模板。本批未运行 Godot、未连接公网、未访问凭证、未导出游戏包，也没有真人结果。拿到同版本游戏包后，由用户组织实际两端测试。

只允许房主与客机直连游戏流量；信令节点只交换 SDP/ICE，STUN 只辅助地址发现。**禁止 TURN、relay ICE candidate、VPN/隧道式游戏流量中继及自动回退游戏中继**。公网不可直连时应明确失败，不能借独立服务端模式冒充 P2P 成功。规则权威须在房主机器；真人掉线不得交给 AI 托管。

## 1. 静态事实不是公网证明

本批仅只读核对以下源码片段；后续源码或包变化时重新核对并记录版本：

| 静态检查目标 | 本次看到的事实 | 不能推出的结论 |
|---|---|---|
| `scripts/net/transport/webrtc_link.gd:33-45` | 配置白名单只接受 `iceServers`、`urls` 与 `stun:` URL | 现场 STUN 可达、NAT 可穿透 |
| 同文件 `:84-108` | 拒绝含 `typ relay` 的描述，候选类型白名单为 host/srflx/prflx | 已选中的 candidate pair 实际直连 |
| `scripts/net/p2p/p2p_signal_client.gd`、`p2p_signal_server.gd` | 存在 `handshake_seconds` 与截止时间处理，源码默认 30 秒 | 每个导出包、每个入口都在 30 秒失败，或该时间等于底层 ICE 超时 |

静态检查状态是 `source_inspected`，不是测试通过。本批 JSON 格式验证也不是游戏运行测试。现场默认值以包的实际配置为准；不要把信令、候选收集、ICE、数据同步的超时混记为同一项。

## 2. 用户拿包后的准备任务

- [ ] 两名真人、两台实际设备 H/G，位于不同公网出口；另备独立信令节点 S（信令模式）。同机双实例、同 Wi-Fi 和 NAT 回环仅可作辅助，不计跨网验收。
- [ ] 记录游戏包版本/哈希、对应源码修订号（无法映射写 unknown）、平台、WebRTC 扩展是否加载、测试人员匿名标签、开始时间与时区。双方必须使用同一包。
- [ ] 用匿名标签记录家庭路由/手机热点/独立公网、不同运营商、IPv4/IPv6/双栈、是否疑似 CGNAT/双重 NAT；公网出口关系须现场私下确认，仓库只记 `different/same/unknown`。
- [ ] 现场确认 STUN DNS 解析与真实 STUN 请求/响应，分别记录 H/G 结果。ping 或 TCP 连通不等于 STUN UDP 可达。
- [ ] 设置可恢复的测试防火墙规则，仅限制测试进程/目标端口；记录原配置并在故障测试后恢复。不得关掉整机防火墙、暴露管理端口或收集账号密码。
- [ ] 从仓库复制矩阵到**仓库外**的私人报告目录，例如用户自行选择的报告文件夹；不得直接把实测敏感日志追加到仓库模板。

NAT 记录拆分映射行为（endpoint-independent/address-dependent/address-and-port-dependent/unknown）、过滤行为、CGNAT 与双重 NAT。可附 cone/restricted/symmetric 的工具诊断标签，但必须注明工具与证据。路由器品牌、热点类型、一次 STUN 成功都不能证明 NAT 类型；未知不阻止尝试 ICE。

## 3. 网络 × 模式矩阵

JSON 的每条任务初始均为 `pending_user_test`，每个模式单独记录，交换 H/G 再测。基础场景至少每方向各做 3 次独立新握手（每次新建房间，不复用既有连接）。

| ID | 现场组合/扰动 | 模式 | 主要验收 |
|---|---|---|---|
| CN01 | 不同公网出口，至少一端明确无 NAT 或已确认可入站 | 手动 + 信令 | 正向基线、权威位置与双向业务 |
| CN02 | 两个不同家庭路由/公网出口 | 手动 + 信令 | 家庭 NAT、不同运营商 |
| CN03 | 家庭路由 ↔ 手机热点 | 手动 + 信令 | 热点/可能 CGNAT，交换房主 |
| CN04 | 两个独立手机热点，优先不同运营商 | 手动 + 信令 | 双侧限制 NAT；失败也必须可诊断 |
| CN05 | 已有证据的双重 NAT/CGNAT/地址端口相关映射 | 手动 + 信令 | 不保证打洞成功，不允许中继兜底 |
| CN06 | IPv4-only ↔ IPv6-only/双栈 | 手动 + 信令 | 地址族兼容；无公共可用地址族可明确失败 |
| CN07 | STUN 正常、单侧阻断、双侧阻断、DNS 失败 | 手动 + 信令 | 分阶段诊断；无 srflx 不等于必定不能 host 直连 |
| CN08 | 正式直连业务稳定后只停止/阻断信令 | 信令 | 旧直连继续，新握手失败，不混淆恢复 |
| CN09 | 建连前信令地址/端口错误、服务不可达 | 信令 | 有界失败与可重试，不假报连接成功 |
| CN10 | 信令可达但阻断对等 UDP/候选端口 | 手动 + 信令 | ICE/握手有界失败，提示可区分，无无限等待 |
| CN11 | 直连后断开客机网络，再恢复 | 手动 + 信令 | 真人掉线显示，恢复按真实入口操作，不 AI 托管 |
| CN12 | TURN URL / relay 候选反例 | 手动 + 信令 | 入口拒绝非法配置，无游戏中继流量 |

CN05 若现场网络不可得，记 blocked 与原因，不能猜 NAT 或填通过。CN12 仅使用获准的无凭证测试输入；若正式 UI 不支持注入候选，记不可观测/阻塞，不能把源码拒绝条件填为真人通过。

## 4. 每次执行步骤

1. 填匿名网络标签和 NAT 证据；确认不是同出口。记录包标识与实际各阶段超时配置，不修改生产源码。
2. **手动 P2P**：按正式界面生成/交换当前 offer、answer 及所需 ICE 信息。交换用受控私人渠道；完整邀请码/SDP/候选原文不得落仓库。记录生成、交换、接收、连接的相对时间与是否候选收集完成。
3. **信令 P2P**：按正式大厅入口配置实际 STUN 与可用信令地址；分别确认创建、加入、offer/answer、候选交换、ICE 和业务就绪。WSS/TLS 是否可用单独记录；源码允许 wss 不代表部署证书验证通过。
4. 通过正式入口完成数据同步、准备、选人、进入对局，双方至少各做一项合法真人操作，核对房主权威结果与客机过滤快照。记录业务编号/相对时间；仅 `connected`、房间码出现或连接灯变绿不算业务通过。
5. 收集已选 candidate pair 类型、地址族、传输协议与对等流量证据。API 不可观测时明确记 `unobservable`，不得编造 selected pair。仅看收集的候选列表不能证明实际选中的路径。
6. 在房主机器通过进程树/批准的日志确认权威位置，S 不启动规则或保存对局。监测 S 应用日志与流量分类，STUN/信令不算游戏转发。
7. CN08：记录关闭信令时刻，仅关闭 S/信令通道，H/G 游戏与网络保持运行；旧局继续至少 60 秒，双方各做至少 3 项合法业务操作并接收权威更新。随后第三个新连接/新房间握手应有界失败。客机断开后的重新握手与旧连接存活分别记录；手动重新交换可另立记录，不冒充信令恢复。
8. 故障场景记录首个失败阶段、实际耗时、配置预算、实际 UI 文案、错误码/日志线索以及清理后能否新建重试；恢复防火墙/服务配置，再重新建立基线。

60 秒观察和 3 次重复是本计划的验收取样要求，不是生产参数。无现场超时配置时先记 unknown，记录最长人工等待与中止原因，判未验收/缺陷候选，不能假定源码默认值已生效。

## 5. 失败诊断与判定

| 现象 | 优先证据 | 分层结论 |
|---|---|---|
| WebRTC 初始化失败 | 扩展加载/平台错误、包哈希 | 包/平台问题，不直接归因 NAT |
| 信令创建/加入失败 | DNS、目标端口、WS/WSS/TLS、响应错误 | 信令阶段失败，不叫 ICE 失败 |
| 没有 srflx | H/G STUN 请求/响应、DNS、UDP 阻断 | STUN 不可达或不可观测；不能仅凭 ping 判断 |
| 收集完成但无连接 | 实际交换候选、NAT 证据、对等 UDP、地址族、截止时间 | ICE/网络限制候选原因；无证据写 unknown |
| ICE connected 但无业务 | 数据同步屏障、鉴权/会话错误、首个业务收发 | 业务阶段失败，不算直连业务通过 |
| 断信令旧局停止 | 精确关闭对象、对等流量、双方日志与 UI | 是否错误依赖信令；排除同时断网 |
| 超时无提示或不能重试 | 阶段时间线、清理状态、重试结果 | 失败处理缺陷，不能用 NAT 限制掩盖 |
| 发现 relay/TURN 或 S 转发游戏 | 配置、选中 pair、S 流量/应用证据 | 边界失败，立即停止该场景，不允许算 P2P 通过 |

结果使用 `pass/fail/blocked/inconclusive`；模板保持 pending。严格 NAT 的“连接失败但有界提示且无中继”可记为负向行为 pass，但 `direct_connection_established=false`，不得宣称该网络已打洞成功。缺少直连/权威/双向业务关键证据时结果只能 inconclusive。

## 6. 数据隐私和交接门槛

- **公网 IP 不写入仓库**。原始地址、端口映射、完整 SDP/ICE、抓包、邀请码、账号标识等只存仓库外受限目录；密码、令牌、私钥和恢复票据不收集。
- 仓库可记录匿名网络标签、不同出口关系、候选类型、地址族、耗时、脱敏错误文案、脱敏证据 ID 与校验哈希。不得把 IP 换成可逆编码或低熵地址哈希后提交。
- 发布日志/截图前人工审查并脱敏；证据哈希针对脱敏副本计算，原始抓包不得公开上传。
- 记录每个场景两模式/两方向/每次尝试，失败不得删除；缺设备/网络/观测接口写明阻塞。
- 核对全部矩阵后才给出覆盖范围结论，不能用一对家庭网络的成功宣布“所有 NAT 可用”。当前整体状态仍是**等待用户拿包真人跨网验收**。

现有 `docs/p2p-authority-public-acceptance.md`、`tests/fixtures/p2p_public_evidence.template.json` 与 `tests/validate_p2p_public_evidence.py` 可作为证据专项补充；证据校验器只校验材料结构/文件/哈希，不证明现实网络事实，本批未执行该校验器。
