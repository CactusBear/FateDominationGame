# 单人与联机战局 UI 一比一迁移与验收

## 本次明确要求

以正式单人 `assets/scenes/game_scene/battle_board_v2.tscn` 与 `scripts/game_scene/battle_board_v2.gd` 为基准，检查全部 UI 相关代码，在联机模式保留相同的贴图、布局、默认状态、刷新、动画、可见入口和操作反馈。不是照旧 tactical_board_ui 另造一套，也不是只补截图中几张图。

规则计算留在房主或独立服务器，联机客户端只显示授权快照并提交意图。真人掉线不交给 AI。对手暗置牌、未公开从者、他人手牌等隐藏信息不得用本机同名模板补出。单人的本地调试改规则与联机权限控制需单列，不以复制 UI 为由开放未授权规则执行。

## 全量源码入口清单

`docs/multiplayer-ui-function-inventory.txt` 从当前 v2 全文件生成，294 个顶层函数，无重复或遗漏；记录定义行、presenter 是否直接调用同一共享函数与待验收状态。48 个函数被 presenter 直接调用只是静态复用证据，未直接调用不等于缺失，仍需追踪 `_ready`、`_process`、`_input` 的网络分支和共享调用链。这个索引不是全部功能通过的声明。

## 本批主代理改动

1. 网络refresh此前只写牌堆数量、未绑定Back1/Back2；现在调用单人 `_bind_pile`。局势弃牌不再强制隐藏，公共 `situation_discard` 接入生产者和接收器白名单及卡数据检查。
2. 未部署时的默认魔术工房复用现有显式 `MapData.areas` 顺序；权威view_builder按同一顺序发送战区，不靠尺寸或名字猜映射。
3. 单人的离开卷轴后返回默认区逻辑抽为 `_update_default_area`，单人及网络每帧均调用。网络初次入场也选择默认区。保留原等待时长和动画。

## 验收标准

BUFF交互以单人悬浮说明为准，不以左键打开作为验收替代。本方状态栏及对手抽屉复用 `_bind_entry_info` / `_update_hover_zoom_keepalive`，真实窗口确认不点击自动展开、停留保活、移入说明可读、移开自动收起；包含两张悬浮截图保存的浏览专项55项通过。主模型原生核对本方与对手截图均显示正确说明，无异常色块。此处现有共享实现已具备悬浮行为，本轮补正了此前只测点击的验收缺口，不另造联机点击模式。有图BUFF的卡图放大与说明入口仍须按共享单人数据声明核对，不把本次无图BUFF测试扩称所有图像状态通过。

每项须关联单人入口、网络入口、数据生产/接收契约、正反例测试与实际结果。函数存在、按钮存在、静态解析及进入对局不算一比一迁移完成。UI验收以正式v2非headless窗口、真实鼠标/键盘、截图原生查看为准；合法操作走权威规则，不手改阶段冒充推进。

`net_server_one_round_test` 增补未部署默认魔术工房、4常驻牌堆贴图、部署后本地默认区实际展开，沿真实worker完整回合运行。新快照字段最初未更新Mirror白名单，实际流程拒绝；已补相同严格接收验证，不放宽未知字段拒绝。
