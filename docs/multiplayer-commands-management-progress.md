# 对局指令、大厅管理与对手答复组件

## 已实现

- 权威指令入口增加常规出牌、主动发动、确认或放弃、次数与数量选项、选玩家、选牌、选位置。均按连接映射的座位校验；效果答复按触发者校验，允许轮外答复。规则结算复用原引擎。
- 非法选择先预校验再进引擎，避免他人对象、缺少必选牌、越界数量等请求被引擎当作取消。指令触发引擎后，即使返回失败，房间也重新发布真实视图。
- 私有待答提示与战局视图同包发送，只给触发者；选牌暂只给候选 ID、必选 ID 和范围，不额外公开暗牌名称与卡图。
- 大厅新增观战加入、转让管理权、移出所选成员。列表使用连接 ID 元数据，不按显示名定位玩家。准备资格、开局资格与 AI 数量读取权威快照，转让后的客机不读取本地空房间状态。
- 修复踢人原先调用不存在的 ENetMultiplayerPeer.is_server 导致实际连接未关闭；改用协议主机 ID 判定。断开后不再轮询已失效的 ENet 实例。
- 新建 `network_choice_panel.tscn/.gd` 作为可复用的纯会话视图组件，支持确认、放弃、分支次数与数量输入；组件不访问 EffectManager。尚未植入正式 v2 战局。

## 验证证据

- `multiplayer-commands-management-results.json`：13 套专项原始日志；端口冲突套件保留预期 ENet 建监听错误，不宣称完全零日志错误。
- `multiplayer-opponent-ui-results.json`：最后一批 5 套，均通过且无运行错误。
- 实际脚本控制的完整对局：222 次成功指令，到第 11 回合终局。没有调用 AI 托管真人席位。注意这是单进程权威指令完整流程测试，测试决策读取主机规则查询；不是正式客机 UI、跨进程或跨设备完整对局。
- 大厅管理窗口：10 checks 通过，含真实转让按钮、客机管理资格、观战身份、踢人后连接实际断开；已原生查看截图。
- 对手答复窗口：11 checks 通过，实际调用已有 QueueOptionalEffectForPlayers 为对手排入效果，通过真实 ENet 发送私有提示，在客机组件点击确认与提交分支数量，由主机结算。原生查看 `net_opponent_choice.png` 和 `net_opponent_options.png`。
- 选项数量测试验证超范围或次数过多时保留等待；两级目标测试验证主动发动→选项→玩家→目标玩家的牌，非法目标不清空等待。

## 边界与未完成

- 整套联机仍未完成，主菜单入口仍未开放。P2P、独立服务端、死循环预检/保护、完整房间 data 同步、恢复菜单与跨设备验收仍待完成。
- v2 战局尚未改为纯镜像读取，客机不能从正式菜单完成整局。普通移动与牌朝向编辑、广播确认等指令仍未接齐；选择取消的全部边界还需逐类补齐。
- 新组件只显示确认与效果分支，选玩家、选牌、选地点的网络协议虽已实现，其界面尚未加入该组件。大量选项时的滚动、窄窗口布局与最终视觉设计尚未验收。
- 观战加入目前完成大厅身份与权限控制，中局加入后的视图绑定和完整观战战局 UI 尚未完成。
- 转让仅转移房间管理权，运算及连接仍在原主机；不等于主机迁移。不得用测试中的同进程会话代替这一限制。
- 数量和提示字段仍需严格协议 schema 检查；当前网络会话不存在加密认证与重连凭据，不能宣称对公网恶意客户端已安全开放。
- 不删除玩家原始 data，不恢复用户删除的视频，不提交版本库。

本批无新增必须用户决策的问题，技术缺口不是用户选择题。
