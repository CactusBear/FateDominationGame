# 多台 Windows 设备局域网真人验收

## 当前结论与边界

**状态：待用户实测，LAN 未验收。** 本文件与 `tests/real_world_acceptance_v5/lan_matrix.json` 是现场任务清单，不是测试报告。本轮不启动 Godot、不访问凭证、不修改生产代码、不提交 commit。

同进程双 peer、本机双进程、127.0.0.1、localhost、::1、本机连接自身 LAN IP、虚拟机/容器在同一物理宿主上互连，都只能作为预检，不能计作多机器 LAN 通过。静态解析、脚本 RESULT、文件哈希一致也不能替代真人通过正式 UI 在不同物理 Windows 设备上操作。

本次范围是同一局域网的 ENet/UDP 手填 IP 与端口。公网、NAT、P2P/WebRTC、Linux、独立服务端恢复不由本矩阵推导通过。广播发现如要验收，先单独核实实现与发现端口；本计划不假设它已经存在。

## 现场人员、机器和拓扑

- 至少两台独立物理 Windows 设备：A（主机/初始房主）、B（真人客机），每台由真人操作。两台配置可让 B 先以玩家验收，再退出并以观战者验收。
- 三台完整配置：A 主机、B 客机、C 观战。**同时主机+客机+观战以及观战掉线不影响真人等待必须三台实测**，不能用 A 上第二个窗口冒充 C。
- 四台扩展配置：A 主机、B/C 客机、D 观战，验证并发上传、多人掉线/恢复与其他在线成员不受影响。三台/四台不足时相应用例保持 blocked，不降格通过。
- 交换主机：至少再运行一次 B 主机、A 客机，排除仅 A 防火墙或网卡配置正确的偶然结果。
- 每次记录设备标签、Windows 版本、物理设备区别的人工确认、真人操作者、实际网卡/IP/掩码、连接介质、网络配置文件、公有/私有分类、交换机/AP 及客户端隔离。IP 示例只作填写参考，不是检测结果。
- 比如 A=192.168.50.10、B=.11、C=.12、掩码=255.255.255.0；实际同网段关系按现场掩码计算，不按前三段相同猜测。优先有线基线，再做 Wi-Fi 或有线/Wi-Fi 混合；禁止访客 AP 隔离。关闭/绕过 VPN 是用户现场决定，勿改变与测试无关的连接。
- 同一冻结构建及数据基线；记录构建文件 SHA-256、git 修订与未提交改动标识。源码窗口和发行包分别记证据，不互相替代。所有破坏性数据试验只用复制的测试资料，保留原始 data 与存档。

## 手动端口与 Windows 防火墙

已核对 `scripts/net/transport/enet_transport.gd`：`listen()` 使用 ENet，允许 1..65535 的显式端口及绑定地址。游戏为 **UDP**；TCP 通断不证明 ENet 可达。下列 27151/27152 只是本计划自选测试值，**不是代码默认端口**。

| 端口/方向 | 设备 | 操作要求 |
|---|---|---|
| UDP 27151（或现场选定 P）入站 | 实际监听主机 | 仅允许测试程序、Private 配置文件与 LocalSubnet；保存规则名与实际程序路径 |
| UDP 27152（或另一个 Q）入站 | 替换端口/交换后的主机 | 仅在对应复测时开；客户端必须输入相同 Q，错端口不得自动跳转 |
| UDP 到主机 IP:P 的出站与返回流量 | 客机/观战 | 默认出站可用则不加规则；受限策略下由管理员按实际端点允许，记录策略 |
| TCP、发现广播、信令/STUN、内部子进程端口 | 不属于本基线 | 不开放整段，不为本 LAN 手填 IP 验收开放 Godot AI/MCP 调试端口；内部端口只在确有部署需求时另列 |

用户可在管理员 PowerShell 现场创建最小临时规则（本轮代理不执行）：

```powershell
New-NetFirewallRule -DisplayName 'Fate-LAN-Acceptance-UDP-27151' -Direction Inbound -Action Allow -Protocol UDP -LocalPort 27151 -Profile Private -RemoteAddress LocalSubnet -Program 'E:\REPLACE_WITH_ACTUAL_BUILD\Fate.exe'
Get-NetFirewallRule -DisplayName 'Fate-LAN-Acceptance-UDP-27151' | Get-NetFirewallPortFilter
# 测试结束只删本次创建的规则；原有规则不动。
Remove-NetFirewallRule -DisplayName 'Fate-LAN-Acceptance-UDP-27151'
```

必须替换程序路径，源项目运行则使用真实 Godot 可执行路径。不关闭全局防火墙、不改公共网络为私有网络来掩盖策略问题。负例前核对是否有其他程序级 allow 规则绕过端口规则；使用专属、限定程序/IP/UDP端口的临时阻断规则并在结束后删除。记录规则变更与恢复，先停当前连接再复测建连。

现场只读诊断：`ipconfig /all`、`route print -4`、`Get-NetUDPEndpoint -LocalPort 27151`、`netsh interface ipv4 show excludedportrange protocol=udp`；主机保存监听地址和 OwningProcess，与进程树对应。`ping` 只作诊断，失败可能是 ICMP 策略，成功也不等于游戏可达。`Test-NetConnection -Port` 检测 TCP，不能作 UDP 游戏通过证据。

## 留证、日志与时间线

统一归档根：**`E:/Projects/Godot/FateDomination/test`**（不是仓库内 tests）。各机器有 E: 时写本机该路径；没有 E: 时记录真实本机暂存路径，结束复制至主机归档根，不能伪称已写目标目录。本文不创建运行日志或假证据。

每次使用新目录 `<run_id>/<case_id>/<device_id>/`：

- `environment.json`：设备/操作者、构建、数据指纹、IP/掩码、网卡、端口、绑定地址、Private 策略、房间 ID、角色、实际 authority_host_mode。
- `app.log` 与实际游戏/权威子进程日志副本；原日志路径另记，不能假设游戏自动输出到归档根。每次启动用新日志，严禁旧 ready/RESULT 作为本次成功证据。
- `processes.csv`：实际主机与客机 PID、父 PID、程序路径、监听端点；存在权威子进程时记录机器、room/PID/instance_id 的对应关系。不把 authority_host_mode 标签当作实际部署证明。
- `timeline.csv`：event_id、case_id、device_id、operator、ISO8601 时间（带时区）、本机单调毫秒/相对起点、时钟偏差、room/member/seat、room_revision/data_revision/view_seq（可取得才填）、操作、结果、证据路径。协议未暴露的字段填 unavailable，不编造数值。
- `screen-*.png`/录屏：A/B/C 的同一事件对应视角，真实按钮、错误文案、同步进度、房主标签、等待提示与恢复结果。录屏与日志互相对齐。
- `capture.pcapng`：用户授权后用 Wireshark/Npcap 捕获实际物理网卡，过滤 `udp port 27151`（换端口同步修改）；至少主机与一台客机，记录真实源/目标 IP、端口和双向流量。数据同步/断网/重连必须有捕获或明确的抓包缺失说明，缺失时不宣布完整证据达标。
- `result.json`：逐断言实际结果、开始/结束时间、失败原因、操作者与复核者、关联证据。哈希只证明文件完整性，不证明网络路径、隐私或通过。

现场先记录 `Get-Date -Format o`、`w32tm /query /status`，不由代理擅自调整系统时钟；不一致时记录估计偏差，用事件标记和相对时间对齐。时间线至少覆盖：监听就绪→错误/正确入房→同步开始/完成→批准/准备→选人/开局→转让→断网→检测/暂停→重新建连/认证→新快照/数据确认→原待答→继续动作/终局。

**敏感材料保护：** 用户仅在程序本地界面输入本次一次性房间测试密码；不要提交密码、私钥、恢复票据或完整认证报文到文档/JSON/聊天。抓包可能含密码或私有状态，原件限现场受控目录，不上传、不提交 Git；共享报告仅记“正确/错误/空密码”与脱敏字段。隐私验证由各真人查看自己的合法视角与授权的本地证据，不公开他人隐藏手牌。

## 执行与签收规则

1. 用户在场填写设备表及临时防火墙规则，确认构建相同、网络同段；按矩阵最少设备数分配真人角色。
2. 先 LAN-01..05，再同步/批准 LAN-06..08、观战/转让 LAN-09..10、断网/重连 LAN-11..15、完整局 LAN-16；独立负例使用新房间/新 run，不让上例脏状态污染结果。
3. 每个子步骤逐条签收；观察超时必须预先记录现场期限，记录断线检测/恢复耗时，不临时延长至成功后倒称满足指标。本计划未制定产品 SLA，耗时只记录观测值。
4. `pending_user_test` 表示未执行；`blocked` 表示设备、入口或证据不足；`failed` 保留实际反例；`passed` 只在独立物理设备+真人 UI+全部断言+对应证据齐全后由用户/复核者填写。复测用新 run 保留旧失败。
5. 必做用例任何一个 pending/blocked/failed，整体状态不能为 passed。仅两台完成时报告“两机子集”，三机同时观战和四机并发仍待实测；不得修改最低机器数来求全绿。
6. 现场结束只恢复本次网卡/规则调整，保留原始 data/存档及受控证据。共享报告列构建、拓扑、已执行 ID、失败/阻塞、未执行项，不把本机预检或子集通过升级为完整 LAN 验收。

**必须用户真人现场执行：全部 LAN-01..16，以及防火墙授权、物理断网、正确/错误密码输入、合法身份重连、私有视角检查和最终签收。代理当前只能验证文档/矩阵格式与覆盖，不能声称任何现场用例通过。**
