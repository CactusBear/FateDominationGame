# 联机死循环保护实施进度

## 已接入并验证

- `scripts/net/rule_loop_analysis.gd` 只读分析批准 JSON 的效果和显式时点派发，按强连通分量列出风险环组。
- 移除有限节点后的子图仍有环时，不能用同组的有限支路降低风险。`max_total_uses` 仅在存在 `options` 时按引擎语义识别，存在 `options` 时不读取引擎忽略的顶层 `funcs`。
- 变量时点、运行时创建与延迟效果标为未知。延迟步骤不算父效果立即派发；不执行任何效果来生成静态报告。
- 分析有可配置的节点、边、遍历及深度预算；不足明确标为不完整，不当作通过。
- 独立数据校验进程对批准清单中的真实 JSON 写出 `loop_analysis`。高风险不会自动拒绝数据，分析不完整则不通过此次校验。
- 正式数据窗口在应用前展示高风险确认，完整报告可滚动；显式 `_plan.files` 与 `_plan.sources` 关联提供者和原始路径。取消不改规则，房主确认后才应用。
- `scripts/match/rule_random.gd` 提供受跟踪且可恢复的随机流；整数、浮点、洗牌和 AI 随机选择复用此入口。未跟踪的全局随机明确为未知，结束会话清除跟踪。浮点取样对齐原生双精度消耗顺序，包括零样本遇到范围差值溢出的运算。
- `scripts/match/rule_state.gd` 提取重放器现有规则对象图采集，保留原重放检查点内容。运行时调用方可显式传入执行上下文和随机状态，不凭棋盘状态推测它们。
- 独立 `capture_graph` 入口记录数组与字典的共享引用、循环引用和原生类型约束。旧存档参数编码不采用这套单向图格式，不能反序列化它来执行对象或 Callable。
- 集合数量和身份比较都有可配置预算；采集错误必须检查 `ids.error`，超预算的部分图不支持确定性判定。全模板夹具显式扩大比较预算；不把该夹具通过描述为默认预算能完整采集所有数据。
- 效果引擎在真实函数入口记录调用栈、解析后参数、原效果运行游标；三个既有循环显式记录当前迭代、循环体位置、固定遍历范围及已完成结果。`capture_runtime` 从引擎取得活动和已暂停上下文，并合入规则随机状态。
- 显式启用的 `rule_budget.gd` 支持步骤预算和协作时间软预算。权威引擎只在完整函数之间或已记录且可续行的循环边界暂停；保存原函数、参数、游标和部分结果，返回值只在真正完成时写回。默认关闭，大厅已有显式开关；这不是完整死循环保护。
- 大厅场景预置协作预算开关、步骤与时间输入、应用按钮和能力边界说明。房主只在大厅阶段修改 `settings.runtime_guard`，修改清除准备；无效输入与非房主请求不改房间。整数文本输入与内部 JSON 无损编解码保留 int64 精度，时间输入保留实际小数，0 表示对应限制不限。
- `LobbySession` 将房间显式预算传给权威启动入口；`GameStart` 先校验，再在重置之后、开局规则之前应用配置。结束会话清除旧预算。独立服务端内部 JSON 将步数编码成规范十进制字符串，子进程严格还原与校验，实际房间和网络协议仍使用整数。
- 保存的子调用入口不重复扣费，避免小预算在恢复外层时耗尽而永久空转。原生方法未声明可恢复状态时不在其内部强制中断；这不是硬执行时限。
- 正式房间协议新增独立 `guard_continue` 管理请求，复用真实连接成员校验，再校验房主、进行中的房间和最新对局视图；暂停期间统一拒绝普通规则指令并停止自动推进。管理权与计算权分离，转让房主后立即刷新继续资格与视图版本。
- 正式 v2 复用 `NetworkChoices` 图层与既有主题展示异常面板，房主看到玩家、来源牌和效果并选择跳过或重开，其他玩家只显示等待。预算原因、步数、参数与函数栈不发送到界面；房主专属诊断不会进入客机视图。
- 关闭已启动的权威会话时，无论是否曾切换房间数据根，都复用 `GameStart.end_session()` 清理执行引用；客机关闭不清除主机执行。已有数据根恢复流程避免重复结束会话。
- `defer_until_runtime_guard_complete` 接受调用方显式保存的外层尾部，不猜恢复方式。原效果链真正完成后续行；尾部再次暂停时先完成其内层续行，再执行剩余外层尾部。结束会话会清空尾部，回调自身重置会话时也不能重新接回旧队列。运行时采集显式包括尾部队列，普通录制检查点不混入这些尚未接入录制的执行状态。
- `RegularPlay.submit_group` 已保存费用、入场、词条、亮出和打出时点的阶段与卡牌游标；费用效果暂停后不提前扣费、入场或写完成事实。保持整批入场后才逐张派发打出时点的原口径；不重复派发已进入的时点，不重复扣费或完成。
- `RegularPlay.add` 复用同一阶段续行，增量入口显式跳过整组额外牌判定与真名预结算，完成判据仍单独复用原有上限和无合法加牌查询。费用暂停不提前入场，首张完成后仍可独立加牌。
- `ReleaseTrueName` 保留调用方声明区域和对象去重，保存翻牌游标与已展示数量。先完成当前技能的亮出效果，再翻下一张，全部完成后才记录解放事实。类级回调不依赖临时 operation 实例存活。
- 预算恢复期间保留原批次的 `is_running`，避免结束时点把新排入的真人待答队列清空。预算续行后仍要等待真人接受或拒绝；等待期间不执行原生尾部，退出会话丢弃待答和尾部。
- `GameProgress.begin_phase` 保存固定窗口、计划事件、阶段开始时点与首位玩家推进的显式尾部。阶段开始效果预算暂停期间不改变当前行动者与玩家游标；恢复不重派阶段开始，完成后才推进首位玩家。
- `GameProgress.start_round` 保存逐人重置、回合固定窗口、补牌、局势、回合开始时点、事件放置和阶段推进的阶段游标；暂停后不重新建立回合边界，不重增回合号。补牌顺位仍在重置效果完成后读取，原补牌、局势和事件原语内部行为未改。
- `GameProgress.start_game` 在开局固定窗口与开局时点之后分别登记尾部；开局效果真正完成前不启动第一回合，恢复不重复洗牌、发牌或清日志。
- `EventResolver` 的计划放置与计划亮出保存计划、战区及事件游标；每张明置事件效果完成后才继续下一项。续行使用类级回调，不依赖临时实例。事件集合仍在处理时读取，不复制未来事件清单。计划亮出新增 `start_reveal` 完成状态入口，控制台在完成前不报告最终数量；同步兼容入口在暂停时仍只返回当时已完成部分。
- `SituationResolver` 的亮出链完成后才派发 `SITUATION_ACTIVATED`，避免暂停期间提前写入生效历史；类级尾部保存本次局势对象，不重抽或重新发魔力。逐人魔力发放也已保存玩家游标，首位玩家魔力效果暂停时不提前给后续玩家发放；同步取消仍属于不可暂停原生区间。
- 成功 `guard_continue` 复用 `GameLog` 写入独立 `room_management` 事实，记录真实连接、视图版本、续行前后暂停状态，不携带效果名或执行参数。权限拒绝、旧视图与已移除成员请求不记作成功；只完成继续动作记录，不代表暂停、配置、终止与存档管理记录已全部接齐。
- `DrawCardFromPlDeckToHand` 的抽牌效果完成后才派发牌区移动通知，`CardZones` 的离开效果完成后才派发进入时点。`RefillHand` 保存目标、原始手牌与牌堆数量、已抽数量和抽牌后判定阶段；暂停不抽下一张、不提前写完成事实。原生同步返回数量在暂停时仍是部分结果，返回值消费方不应以此作为最终数量；此项未声称已解决。
- 同步 `before_*` 动作栈属于不可恢复原生区间，预算不在栈内暂停，防止动作已返回且弹栈后才执行取消或改写。外侧可恢复循环仍检查预算；不是硬超时保证，长耗时或不终止的同步原生区间仍需独立策略，不能据此启用完整保护。
