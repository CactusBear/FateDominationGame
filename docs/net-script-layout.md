# `scripts/net` 目录约定

网络代码按职责分组，目录调整只改变资源路径，不改变 `class_name`、协议字段或运行时职责。

| 目录 | 职责 |
|---|---|
| `transport/` | ENet、WebRTC、底层分片与清单/目录传输 |
| `p2p/` | 邀请码、手动 P2P 与信令服务 |
| `identity/` | 身份密钥、用户名、注册表、密码、继承和旧档迁移 |
| `session/` | 大厅会话、房间状态、本机权威客户端 |
| `authority/` | 权威规则入口和选人权威 |
| `content/` | 内容目录、缓存、房间资源、数据组装和同步 |
| `validation/` | 内容校验、循环分析、随机预检和校验子任务 |
| `server/` | 独立服务端启动、网关、房间 worker、控制台、信号和恢复策略 |
| `ui/` | 大厅、房间数据、组合选择和 v2 网络视图控制器 |
| `ui/legacy/` | 仅测试场景使用的旧手牌组件，暂不删除 |

## 维护规则

- 新脚本先判断职责归属，再放入对应子目录；不要按调用者重复复制。
- `class_name` 保持稳定，跨目录依赖使用 `res://scripts/net/<category>/<file>.gd`。
- `data_catalog.gd` 与 `room_data_assembler.gd` 存在双向依赖，修改时作为一个组检查。
- 服务端 worker 启动仍通过既有场景路径，移动脚本时必须同步场景 `ext_resource`。
- 目录整理不等于功能完成；正式入口仍需专项测试和非 headless 窗口验收。
