### 十三、暗置牌与效果扫描口径（裁定，含主代理误解的二次修正）

用户逐字（第一次）：「暗置牌也要扫效果，只不过暗置牌不算激活，大部分效果依赖激活，且其他效果通常不能作用于暗置牌这种未知效果的卡，但不要写死」。

用户逐字（第二次，直接纠正主代理）：「**事件牌不需要判断激不激活，事件牌的效果只要正面就生效，暗置不等于不激活，只是常规情况如此，不要写死**」。

- **扫描 ≠ 生效**：`MapAreaHasEffect` **不得跳过扫描**（暗置牌也要扫到）。扫描是**存在性**判断，与 `BoardHasEffect` / `PlayerBuffsHaveEffect` 同一口径 —— `effect_manager.gd:1776–1777` 自己写明"口径与这几个查询入口一致"。
- **★ 事件牌不判"激活"★**：事件牌**没有**激活概念，**不套 `_need_activate`**；它的效果**只要正面（非暗置）就生效**。
- **★ 暗置 ≠ 不激活 ★**：两者是**不同概念**，不可等同。"暗置通常不生效"只是**常规情况**，**不得写死**。系统里已存在"暗置也生效"的例外效果（如 `CountsPowerWhileConcealedEffect`：暗置仍计威力）→ 这类例外应由**效果自身声明**表达，而**不是**在查询入口硬编码 `_is_concealed` 判断。
- **主代理纠错留痕**：我曾把"暗置"与"未激活"当成同一件事，并据此提出"在 `card_state_allows` 补一条暗置=未激活"——**该提案作废**（既混淆了两个概念，本身也是"写死"）。同时"纯查询偷偷建库"那条与此无关，不受影响。

### 十二、非 headless 测试要弹 Windows 系统通知

用户逐字：「**非headless测试时，要调用Windows系统通知，告诉我这个时候能不能操作电脑**」+「**窗口是否必须在前台也要通知**」。

- 工具：`tools/win_notify.py`（无第三方依赖，PowerShell + WinRT Toast，失败自动退化消息框；已实测可弹）。
- 两个通知点：测试**开始**（马上会抢鼠标/键盘）与测试**结束**（异常/超时/Ctrl-C 走 finally，不漏）。
- **"是否必须前台"由调用方显式声明，不写死**：
  - `foreground_required=True` —— 测试靠真实前台窗口收输入（外部真实 OS 点击类，如 UI 窗口验收）。切走窗口点击会落空、测试假失败。
  - `foreground_required=False` —— Godot 自己驱动窗口（引擎内部输入/截图）。窗口可在后台，但**不要最小化或完全盖住**（可能拍不到画面）。
- headless 路径**必须完全静默**（不占用桌面就不该打扰）。
- 已接线（均 `foreground_required=False`）：`tools/run_refactor_window_baseline.py`、`newtests/run_round71_shared_discard.py`、`run_round74_out_of_game.py`、`run_round75_banner_layer.py`。
- 待接（`foreground_required=True`）：`newtests/ui_final_runner.py`（UI 写者负责）。
- **约定**：以后新增任何会拉起真窗口的 runner，都必须接上这一对通知。
- **★ 根本解（用户反馈"某次弹窗口没通知"后补上）★**：只在 runner 侧接是**不可靠的** —— 任何一条启动路径漏接，用户就会在不知情下被抢走鼠标键盘。因此改为**项目侧兜底**：新增 autoload `WindowOccupancyNotice`（`scripts/system/global/window_occupancy_notice.gd`，已注册进 `project.godot`），**窗口一出现就通知**，与谁拉起无关。
  - 判定方式**显式声明**：只看用户参数（`Godot ... -- window`，即 `OS.get_cmdline_user_args()` 含 `window`）。正式游戏不带该参数 → **绝不弹**；headless 测试也不带 → **静默**（已实测：真窗口 2 条 / headless 0 条）。
  - 项目侧负责"开始" + "正常退出的结束"；runner 侧保留作**强杀/超时兜底**（那时 Godot 的 `_exit_tree` 不会执行）。两侧文案可能先后弹出，Toast 会以后者覆盖前者显示，属预期，宁可重复不可漏。
