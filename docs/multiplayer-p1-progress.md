# 联机 P1/P2 实施进度

## 当前阶段

P1 存档内核已实现并运行验证，但普通菜单与 v2 自动录制、任意调试操作记录尚未接入；不能称为玩家可直接使用的完整恢复功能。P2 当前为视图生成与镜像校验，未替换 v2 的全部直接规则读取。P3–P6 尚未完成。

后续由主代理串行实现，不再使用子代理。需要用户决定的事项集中到 `multiplayer-open-questions.md`。

## P1 已实现

- MatchJournal：长度帧、64 位值、序号与校验链，拒绝对象反序列化；尾部截断识别与完整记录恢复，正常存档续写。
- NetIds：会话弱引用 ID，同名不同对象不合并；已知本局 data 路径标准化；规则对象图快照包含属性及对象共享关系。
- MatchReplay：显式 begin/perform/pulse/restore/resume_recording/release；本局 data 副本、源码及引擎版本哈希、动作随机入口、操作前后状态校验、等待输入与帧续行。
- 广播等待消费者的启用是显式录制动作，不把恢复界面本身的节点引用写进存档。
- 状态检查包含玩家、注册表、规则池、地图、待答队列、暂停 runs、AI 尝试集合与事实日志；排除展示消息和含实例号的展示差值快照。它不是完整通用快照反序列化器，也不能拿来宣称对任意规则组合证明停机。

## P1 未完成/限制

- 记录入口需显式调用；未经入口的状态改变会拒绝续录，而不是悄悄漏记。
- 恢复目前用于本机受信任存档，不是网络任意上传存档接口；恢复会重置当前对局。
- 截断存档目前可恢复完整前缀，但不能直接续写原文件；另存分支恢复仍需实现。
- 完整规则图逐步校验开销较大，记录与重放耗时已保存，不适合直接当每帧网络状态。
- 当前源码严格匹配，新增脚本亦可能令旧存档版本校验失败；正式版本兼容与迁移需另做显式版本策略。
- 缺少完整真人交互录制、全部暂停续行路径和恢复中局窗口可操作性覆盖，不能仅靠全 AI 终局测试推断这些都完成。

## P2 当前成果

- ViewBuilder 按白名单输出视图，不把完整规则对象图发送给客机；私有手牌和未公开从者信息过滤。
- ViewMirror 深拷贝存储并拒绝旧序号、未知字段、字段缺失、错误类型、重复玩家/地图 ID、非法位置占据者与隐藏牌面标识。
- 新增五类恶意/畸形数据反例：先验证报红，再加强校验；最后真实 AI 对局经过视图回环到终局，205 checks 通过，无运行错误。
- 镜像已增加显式观察者绑定：切换房间/观察者必须调用 reset，拒绝其他视角、错误控制关系和他人手牌。新增反例先报红；最后包含完整对局视图回环的 203 checks 通过，日志无错误。随机对局长度不同会使 checks 数变化，不能把不同批次的总数当作增删固定断言数。
- P2 尚未完成：全部游戏显示字段、合法操作与私有选择提示、事件流、v2 只读镜像接线和网络信任来源验证。不能把当前数据回环称为客户端已经可联机游玩。
